## Single-phase subagent mode

Offer this compact mode for a genuinely small, bounded one-phase task or small debt/fix. With the
owner's explicit mandate, the existing `/tfw-plan` agent remains the sole Coordinator and owner
interface; no separate GATEWAY is required. It leads the full TFW cycle through distinct Researcher,
Executor and independent Reviewer subagents, without doing their work itself. Launch each with only
`/tfw-* <task[/phase]>`; roles obtain context from task files and return only required vertical TFW
gates, without chatter or solution hints. Advance authorized work and corrections through applicable
docs/knowledge, changelog and safe close without repeated mechanical launch approval; reserved owner
decisions still stop their dependent work. This saves owner clicks, not Coordinator context: explain
this context/noise cost instead of promising GATEWAY-level context isolation.

Each subagent must load its exact workflow, own its artifact, return directly and continue at gates,
use all required tools including browser when needed, and preserve a stable Candidate and role
independence. Re-evaluate scope growth, cumulative context and chat noise. Large or multi-phase work
is ineligible. If a prerequisite fails or the task outgrows this mode, stop the affected delegation,
name the limit and offer the visible-session route; do not silently switch modes, collapse roles or
infer reliability from the existence of an `Agent` tool.
