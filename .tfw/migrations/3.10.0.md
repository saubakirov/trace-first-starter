# Updating to TFW 3.10.0

Full Plan gains an explicit fourth mode: **GOAL**. Use it when the owner can describe an outcome and its acceptance checks, wants one main conversation, and sets a maximum number of external attempts. The approved master HL is the execution and review order. Manual, visible-agent and subagent work retain their TS and correction rules. Daily and Assisted retain their existing contracts.

## Pin the target and choose the route

After publication, resolve `v3.10.0` to its full commit and verify `.tfw/VERSION` there. Before a tag exists, use an expressly authorized full commit and label it untagged. Read the [update workflow](../workflows/update.md) and the applicable guides from that exact source. Installing this version does not select GOAL or authorize a live run.

| Installed version | Ordered obligations |
|---|---|
| 3.9.3 | This guide and the applicable [coordination adoption checks](coordination-modes.md). |
| Any earlier supported version | Follow [3.9.3](3.9.3.md) and its linked predecessor routes in order, then this guide; apply the selected final payload once. |
| Already 3.10.0 | Verify the selected bytes, managed entries and receipt against the pinned source, including unfinished changes. A matching version string is insufficient. |
| 0.x, unknown, unsupported or contradictory provenance | Preserve the receiver and obtain a bounded migration decision; do not run a fresh init over the project. |

## What changes, and only where GOAL is selected

These excerpts identify the prior **3.9.3** rules. Their successors differ only for explicitly chosen GOAL:

| Prior wording | Behavior at 3.10.0 |
|---|---|
| `For new work, explicitly select` followed by `manual`, `visible-agents` or `subagents` (Codex instructions) | Full Plan offers a fourth choice, `goal`, at startup. It still frames the outcome, challenges assumptions and obtains approval of the ordinary HL. There is no separate TFW GOAL command. |
| `master/phase HL and highest approved TS` (Handoff read contract) | For GOAL alone, read the task-local owner-approved HL at its reachable full Git commit. Its positive attempt limit must agree with the task. A missing, draft, wrong-task or unreachable order cannot start execution; do not add a TS placeholder. |
| `Keep the same Executor and independent Reviewer` (coordination conventions) | The three existing modes retain their same-phase correction rules. In GOAL an actual REVISE inside the HL uses a fresh executor and a fresh independent reviewer for the next charged attempt. A failed inner check, compact or native wakeup is not a new attempt. |

For a GOAL result, carry that same pinned HL into closing and any release-readiness evidence in place of the TS. Retain the actual RF, evidence, independent judgment and owner decision. The receiving project's release, version and publication authority still apply.

## Apply the connected files together

1. Use one immutable source for [Plan](../workflows/plan.md), [GOAL](../workflows/goal.md), Research, Handoff, Review, the common conventions/glossary, HL/status/event templates, [economics](../economics/README.md#goal-attribution) and the selected adapter rules, profile and commands. Use the [tooling manifest](../adapters/manifest.yaml) for install/update only: compare full command copies byte-for-byte; merge managed root blocks without replacing project-owned text. Preserve private preferences, custom adapters and unselected surfaces. A conflicting managed change needs its owner's decision. Do not copy this repository's personal settings, traces or maintainer tools into receivers.
2. Preserve current tasks, phase-local authority, journals, frozen HL/TS epochs, grants, knowledge and original numeric receipts/prices. No bulk state backfill, zero-cost placeholders, retroactive GOAL classification or change of active mode. Deliberate mode changes use the existing human selection channel and a safe boundary. Preserve configuration other than the installed version and the selected framework changes.
3. GOAL binds a producer's own measurement source before expensive work. Keep the existing numeric v1 format; the GOAL extension describes only a disjoint observed source range. Count starts from charged dispatches, inner checks from recorded checks, presentations from RF and returned verdicts from REVIEW. Reject an unstarted attempt or unrecorded step without erasing the receipt or last valid report. Missing coverage and mixed ranges remain visible, including research and coordination.
4. Report capability and proof for the actual provider and surface. This release has a live Codex pilot. The Claude Code and Antigravity checks used controlled native-format inputs for the selected collectors; they are not proof that an unattended full task ran in those environments. Use the [Claude Code](../economics/claude-code.md) and [Antigravity](../economics/antigravity.md) recipes; an unsupported source stays a gap. A reviewer verdict, a platform wakeup and owner acceptance are separate facts.

## Verify and retain the receipt

In a disposable check, choose GOAL explicitly with a bounded HL (for example, two attempts). Confirm that an owner-approved pinned HL admits Handoff without TS, a draft or absent HL refuses, and a missing independent reviewer never becomes self-approval. Check one inner retry versus one outer REVISE; the latter consumes another start and respects the cap. Check an ordinary mode on its original TS and correction route. Reconcile distinct preparation, execution and review ranges; do not add overlapping source totals.

Run the receiver's configured checks and record target SHA, applied/preserved/refused files, observed results and platform limits in its usual update receipt. A framework-only receiver can evaluate the semantic checks without installing upstream Python tools. No change to Daily entry, default agent delegation, deployment, publication or personal HTML review format is selected by this upgrade.
