# Updating to TFW 3.10.1

This patch corrects the existing Full GOAL route: the main agent executes and fixes the approved
HL, while research and fresh independent review use separate contexts. It also includes the
reviewed Daily checkpoint simplification and bounded Claude visible-session recipes already
integrated into upstream master. It adds no fifth mode or separate GOAL command.

## Pin the complete target

Resolve published `v3.10.1` to its full commit and verify `.tfw/VERSION`. Before publication,
use only an expressly authorized full commit labelled untagged. Read the target's
[update workflow](../workflows/update.md), this guide and the applicable predecessor obligations.

| Installed version | Ordered obligations |
|---|---|
| 3.10.0 | This guide, including the historical GOAL boundary and selected Daily/Claude changes below. |
| Every earlier supported version | Follow [3.10.0](3.10.0.md) and its linked predecessor routes in order, then this guide; apply the selected final payload once. |
| Already 3.10.1 | Verify exact pinned bytes, selected adapters, receipt and unfinished changes; the version string alone is insufficient. |
| 0.x, unknown, unsupported or contradictory provenance | Preserve the receiver and obtain a bounded migration decision; do not replace the project with a fresh init. |

Read older guides for their preserved obligations. Where this guide gives a scoped successor,
use that successor for new work; do not instantiate an older intermediate GOAL contract merely
because an earlier guide describes it.

## Recognize the changed rules

These excerpts name earlier instructions and their successors, not instructions to replay.

| Earlier wording and source | Successor and scope |
|---|---|
| `An explicitly designated fresh first Executor may instead take the handoff.` — 3.10.0 GOAL | For new `continuous-v1` contracts the main agent executes and corrects; implementation helpers and phase Coordinators are not launched. Researchers and Reviewers retain independent roles. Historical frozen attempt contracts preserve their agreed context arrangement. |
| `At the **start** of each new external attempt` — 3.10.0 GOAL | New contracts count substantive execution steps and separately identify review launches/returns. The proposed defaults are 100 steps and at most 10 between completed reviews, with earlier and final checks; the owner's agreed values govern. Do not translate steps into historical attempts. |
| `Before each orderly turn return` — earlier Daily capture rule | Capture before returning a deliverable or materially revised result, before planned pause/handover, and at close. Pure explanation/status replies need no separate capture. This changes Daily cadence only; see the [adoption boundary](../extensions/daily-task/installation.md#adopting-the-revised-daily-economics-checkpoints). |

Choosing GOAL still does not approve the HL. Resume the unfinished substantive Plan work:
beneficiary, value, concrete future result, alternatives, consequential questions and research.
Reuse already established answers. Ready execution uses the frozen HL without a TS.

An interim CONTINUE is not final acceptance. A completed REVISE resets the rolling review
interval but does not authorize ignoring findings: the Coordinator rules them, then the same
Executor returns to ONB. Final close requires the current full APPROVE with no pending review,
the usual docs/knowledge/economics effects and actual owner acceptance. Compact and host wakeups
neither add steps nor reset the limit. An exhausted limit grants no extra step or owner decision.

## Apply connected files and preserve existing work

1. Install the selected final workflows, conventions/glossary, HL/status/ONB/RF/REVIEW/event forms,
   economics guide/helper and its shared `economics/goal_contract.py` module, configuration defaults,
   and selected adapter sources together. Upstream `tools/tfw_state.py` remains a maintainer tool,
   not a receiving-project runtime requirement. The manifest and briefing template are compatible
   without changing their schema or creating another route.
2. Merge only managed root blocks and compare full command copies with canonical sources. Preserve
   private preferences, project-owned instructions, unselected adapters, task/phase records,
   journals, knowledge, original numeric receipts and saved quotes. Keep explicit existing
   `tfw.goal` values; introduce the defaults only where absent. A conflicting customization needs
   the existing owner's decision, not an overwrite.
3. Existing frozen attempt HLs and `goal_attempt` status keep their historical semantics. Do not
   bulk rewrite them into `goal_step`, invent starts, relabel receipts, silently switch mode or
   add a TS. A deliberate adoption requires the human's bounded contract decision at a safe
   checkpoint, preserving prior history and expenses. The other three Full modes retain their
   routes. Daily and Assisted do not become GOAL.
4. For an already selected optional Daily package, update its canonical skill, economics reference,
   entry sources and selected installed copies as one group through its
   [installation contract](../extensions/daily-task/installation.md). Preserve historical captures
   and the selected local form, and record the adoption point for an open record. API-equivalent
   valuation remains the default unless the owner/project explicitly selects token-only accounting.
5. The [Claude profile](../adapters/claude-code/coordinator.md#self-created-visible-role-chats)
   adds mechanics only for the selected visible-agent route. It does not permit GOAL executors.
   Prompt-free Desktop remains P0; the cited Remote Control observations remain dated P1 evidence.
   Verify actual creator, address, settings, visibility and delivery on the surface in use. No
   warm-up message, history inspection or silent mode switch is authorized by the recipe.

## Verify and retain the update receipt

Check a new explicit GOAL with a frozen HL and its two positive bounds; missing approval or
ambiguous counting refuses execution. Distinguish a started/pending step from a completed one,
an early review from a tool call, and an interim CONTINUE from current final APPROVE. Check
REVISE at the boundary, recovery after compact, a pending replacement review after an older
APPROVE, and the unchanged reading of an actual historical attempt contract. Do not create
new execution just to exhaust the configured maximum.

Reconcile disjoint producer ranges and preserved historical receipts once. Keep preparation,
research, execution, correction, interim/final review and closure distinguishable where measured;
an inseparable range remains shared. Missing or unsupported coverage is not zero, cache is not
added twice, and an unpriced token remains measured. Source extraction limits remain those of
the selected [Claude](../economics/claude-code.md) or [Antigravity](../economics/antigravity.md) recipe.

The GCONT pilot ran live in Codex. Claude Code and Antigravity have structural and supported-format
synthetic checks, not live end-to-end GCONT proof. Neither the older Claude provisioning observations
nor a passing parser proves unattended behavior on a new surface. No comparative savings are claimed.

Run the receiver's own configured checks and record source SHA, applied/preserved/refused paths,
actual observations and limits in its ordinary update receipt. A framework-only receiver can check
the semantic route without installing upstream test tools. Installation does not itself select
GOAL, authorize a live run, merge, publish or deploy.
