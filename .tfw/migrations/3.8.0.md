# Updating to TFW 3.8.0

This minor release adds portable task economics and light framework delivery, and refines the
Claude Code and Antigravity Coordinator profiles. It adds one optional helper and changes
instructions; it changes no task-state schema, routing field or provider capability. Existing
approvals, completed tasks and historical artifacts are not reopened by installation.

## 1. Pin the source and retain the complete route

Resolve published `v3.8.0` to its exact commit and verify VERSION `3.8.0`. Before publication, use
only an explicitly authorized full untagged commit SHA and label it untagged. Read the pinned
target's update workflow, changelog and every applicable guide before receiver writes.

| Installed version | Ordered remaining obligations |
|---|---|
| 3.7.1 | This guide |
| 3.7.0 | [3.7.1](3.7.1.md), then this guide |
| Every earlier supported version, including supported 1.x and 2.0.0 dirty tags | Follow its exact ordered route in [3.7.0](3.7.0.md), then 3.7.1 and this guide |
| 3.8.0 | Verify source identity, selected bytes and any unfinished update before an already-current return |
| 0.x, unknown/custom or contradictory provenance | Stop for a bounded migration decision; full init is not migration |

Read obligations in order; install the selected final payload once. Preserve receiver settings,
personal preferences, project purpose, tasks, frozen approvals, journals, knowledge, economics
records and unrelated work. Earlier guides keep their historical wording; this guide supplies the
successors below.

**This update's own download.** Step 0 runs from the installed `update.md` before a target is
pinned, so a receiver on 3.7.1 or earlier fetches 3.8.0 by its old text, which can transfer about
114 MiB. The operator may ask once for the light fetch shown in the root README section "Updating
TFW". From 3.8.0 on, the installed Step 0 is the light fetch itself.

## 2. Refresh the connected instructions

Refresh all ten canonical workflows under `.tfw/workflows/` (including `research/base.md`),
`.tfw/conventions.md`, `.tfw/quickstart.md`, `.tfw/templates/update_receipt.md`,
`.tfw/adapters/claude-code/coordinator.md` and `.tfw/adapters/antigravity/coordinator.md`.
Synchronize the installed command copies through the pinned tooling manifest. Codex and Antigravity
thin routers keep selecting the canonical workflows; do not install absent adapters or change the
ten-command Full set. Persistent adapter pointers and the manifest keep their pinned bytes.

Install the new economics group as one connected group, following the pinned `update.md` Step 3:
`.tfw/economics/README.md`, `rates.json`, `record.schema.json`, `tfw_economics.py` and
`.tfw/templates/economics.md`. Verify all five at the pinned source and in the receiver. An
identical repeat is stable; customized or conflicting economics files and existing task JSONL or
report data are preserved for an owner decision, never silently overwritten. The Python helper is
optional: ordinary status, coordination, review and the Knowledge Gate need no interpreter, pip
install or runtime.

This repository's root `.gitattributes` and root READMEs are not receiver payload; a receiver's own
README and attributes stay untouched. Set VERSION and both framework-config version fields to
`3.8.0`, merging only framework-owned keys and recording exact source provenance. Include the
matching changelog and this guide.

## 3. Apply changed behavior without rewriting existing authority

| Retired wording / behavior | 3.8.0 successor |
|---|---|
| `update.md` Step 0: "Resolve `tfw.upstream` to a local Git checkout … materialize exactly that object with `git archive` into `.tfw/.upstream/`" | A written light fetch into `.tfw/.upstream/.clone`: blobless, depth-1, cone-mode sparse clone with `core.autocrlf=false` and an empty `core.attributesFile`; a `count-objects` size check that discloses a full download; one fallback; a raw-byte check of every file; the clone deleted after the copy. Pin and provenance guarantees keep their meaning. |
| "Reject … duplicate blocks, drift or second-run diff" | "Reject … duplicate blocks or drift"; a second adapter-sync run is no longer required. |
| "remove `.tfw/.upstream/`/temporary source only when safe" | Remove it; before sealing the receipt, `git ls-files -- .tfw/.upstream` must print nothing, and any entry is disclosed. |
| Receipt template column "Artifact or command" | "Command and its result, or evidence path"; never pasted output. |
| "Full ships no executable, dependency, collector …" | Full ships no executable needed for ordinary lifecycle; the narrow economics exception ships the optional `tfw_economics.py` with its complete readable contract. |
| Closing: DONE, then archive and disposal | Reconcile role economics before DONE; after DONE save and present `economics.md`, then dispose of task-owned resources. |
| New-task startup card without a version row | Its first row compares installed `.tfw/VERSION` with the newest exact `vX.Y.Z` tag at `tfw.upstream` through one `ls-remote` bounded by about 13 s on the agent's own command tool; it never updates, shows `unknown` on failure, and the upstream itself shows no offer. |
| Coordinator profiles keep one-phase work in a single chat without role agents | Single-phase agent mode is an offered owner choice in the Claude Code and Antigravity profiles; outside it the full-chat route is unchanged. |

New or continued task-bound Full units adopt the economics binding at their next activation or
resumption: each role returns only its own numeric JSONL or typed failure receipt, and a Claude Code
subagent's source is `<sessionId>/<agentId>`. Completed tasks need no retroactive economics files.
Frozen HL/TS and ongoing execution stay as they are.

## 4. Verify the selected result

Verify source/ref, VERSION, config versions, changelog and guide agree; affected installed copies
match their exact sources; the economics group is complete and preserved where customized. Check
preserved project settings, historical task bytes and Daily forms. The new Step 0 is first observed
at the next update, and the version line at the next new task. Run the receiver's configured checks
and retain actual results and limits in its update receipt. Upstream additionally runs configured
pytest/MkDocs and staged/release-history Git-blob guards. Source checks do not prove native agent
behavior, provider sandboxes or checks in a receiving project; the Codex sandbox, macOS, Git below
2.42 and hosts without partial-clone support remain unobserved for the light fetch.
