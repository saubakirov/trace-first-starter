checked for applicability when used. Planning no longer requires an unrelated global knowledge batch.
This release retires that live gate/configuration contract while preserving accumulated meaning.

## 2. Complete the prerequisite, preserve, then adopt

Follow [knowledge lifecycle adoption](knowledge-lifecycle.md) as the single detailed TKL effect
guide. An incomplete SLC 3.3.0 connected group must complete or refuse under its pinned guide before
any TKL effect. Keep its exact preserved membership, affected digest pairs, disposition and expected
cuts. A completed SLC receiver needs no repeat historical sweep. A later snapshot cannot invent an
earlier before-image, and a version string or receipt alone proves no completed migration.

At a safe boundary for affected writers, preserve exact source/authority and old/intended inputs.
Install compatible canonical capture/qualification/use/close readers and selected adapter copies
before retiring the old gate/settings. Revalidate each affected write against preservation; refuse
third values, missing evidence or conflicting authority without erasing later work.

Merge only the named `tfw.knowledge` retirements: `interval`, `gate_mode`,
`max_facts_per_topic`, `max_topic_files` and obsolete `max_index_lines`. Remove an empty map only
after its listed children are gone. Preserve unknown custom keys for the existing resolver.
Retain architecture/reference and legacy D/F/source meaning in the stable knowledge entry; remove
only maintained count/inventory instructions. Existing knowledge-state and processed-marker bytes
remain inert history; absence remains absence. New records require their own qualification decision.

Preserve project purpose, root README/RELEASE, configured task/history containers, checks and budgets,
profiles/grants, private preferences, local bindings, topics, task artifacts and immutable journals.
Do not import this repository's knowledge, team or task memory, adopt AT, or reopen sealed work.
Apply still-needed older scope/configuration mappings through their own authority. In this framework
release, VERSION and both framework configuration copies agree at 3.4.0; receiving projects retain
their own product versions. Installed provenance names the configured upstream and verified tag or
authorized full SHA. The adapter manifest schema and briefing template require no version-number rewrite.

## 4. Verify and explain the actual result

Verify the final target, selected reader/adapter identities, config/entry effects and preserved
bytes. Re-observe expected cuts and completed repeats through the detailed adoption guide; divergent
affected inputs refuse the connected operation. Run the receiving project's applicable checks and
inspect actual compiled destinations where that project compiles documentation. Upstream pytest and
MkDocs are maintainer assurance, never newly required receiver runtime.

Complete checks, resolve/disclose cleanup while needed source remains available, seal the immutable
attempt receipt, then render `.tfw/templates/briefing.md` in `tfw.content_language`. Explain actual
outcome, useful changes, preservation, limitations and next action. Release-supported benefits and
observed receiver results have separate grounds. Keep stopped/partial outcomes and prior receipt
epochs truthful; do not claim native success or recipient comprehension from files alone.

A missing authority or failed affected check stops the selected effect. Retain current work and
source/preservation evidence; restore only separately authorized compatible paths, never a whole
old state map or task tree. TFW installation does not release the receiving project's product.
Full TFW is this release's scope; Light, Assisted, OTR and provider admission are unchanged.
