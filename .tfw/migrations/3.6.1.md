## 3. Replace the affected rules, not historical choices

| Retired 3.6.0 wording / source | Successor |
|---|---|
| Plan: "Before each role launch, apply" followed only by the shared Launch selection pointer | Inline gate: choose and justify a concrete model or honor an explicit owner-selected model policy; select supported reasoning effort separately and apply when authorized. |

Separate interface role, agent creation/launch and communication. Then map the understandable answer to the technical fields and briefly confirm it in the same card. |

At new-task entry the card must make clear what the owner gets and why: fewer launch/copying steps,
protected conversation context, independent roles and retained decision control. Identify the actual
current interface role separately from a proposed handover. A GATEWAY presents Coordinator-level
gates/results, never plans or supervises workers; a direct Coordinator holds those operations in the
same conversation. Manual, native and click-assisted starts depend on the current platform. Strategic
discussion and the TFW cycle remain in every mode, not alternatives in the question.

Short vertical TFW status/question/result returns are required by default, not free dialogue or
silence. Manual agent creation does not select owner-transfer. An unclear answer grants no authority;
the card's confirmation is not another approval, registry, role activation or HL/TS verdict.

Existing explicitly selected direct coordination remains valid. An inherited route alone is not an
explicit choice: at first delegation or a mandate change resolve the owner-context handover. Preserve
active work to a safe gate; never silently reparent workers, restart planning, manufacture an owner
decision or bulk-migrate task files. Use the existing selection/amendment route when its conditions
apply. Provider limits and reserved owner decisions still constrain autonomy.

The Codex profile, not common Plan, owns its inspected creation restriction and two model policies:
use the configured default while choosing effort, or reuse specifically owner-named models for the
selected roles. Record the actual owner choice once in existing coordination authority. Do not ask
for a model name at every covered launch, force `high`, or create-then-change as a workaround. The
shared gate recognizes explicit owner policy without imposing Codex mechanics on other providers.
