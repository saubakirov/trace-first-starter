# Updating to TFW 3.9.2

This patch makes Full economics collection finite and its interpretation useful for decisions.
It distinguishes unavailable binding from an attempted extraction failure, keeps measurement
coverage visible and relates approximate resources to comparable accepted results. Numeric v1,
the helper, provider recipes, price records and the 3.9.1 communication contract are unchanged.

## 1. Pin the complete target

Resolve the published `v3.9.2` tag to its full commit and verify VERSION. Before publication, use
only an explicitly authorized full untagged commit and label it untagged. Read that source's
update workflow, changelog and applicable migration guides before changing a receiver.

| Installed version | Ordered remaining obligations |
|---|---|
| 3.9.1 | This guide |
| Every earlier supported version | Follow [3.9.1](3.9.1.md), including its linked route through 3.9.0 and earlier obligations, then this guide |
| 3.9.2 | Verify exact source, selected bytes, receipt and any unfinished attempt before an already-current return |
| 0.x, unknown/custom or contradictory provenance | Stop for a bounded migration decision; full init is not migration |

Read obligations in order and install the selected final payload once through
[Update](../workflows/update.md). Preserve receiving-project settings, task/phase state, journals,
frozen approvals, qualified knowledge, original economic contributions, dated reports, saved
valuation bases, personal preferences and unrelated work. No historical measurement is rewritten.

## 2. Retired wording and its successor

The left column quotes older instructions for recognition, not execution. The common semantic
owner is [Full cycle and finite outcomes](../economics/README.md#full-cycle-and-finite-outcomes);
the active role workflow identifies its own artifact and return point.

| Retired wording / incomplete interpretation | Successor |
|---|---|
| Research: `A missing source field remains null with reason` | Null is valid only for optional fields allowed by numeric v1. Required binding unavailable before extraction is an attributable prose disposition in the existing stage/RES artifact, never an invalid manifest. |
| Full returns described only as `numeric JSONL or typed capture-failure receipt` | Use measured JSONL when capture succeeds, an actual v1 failure receipt when a bound extraction was attempted, or the common prose disposition when required binding was unavailable before extraction. Coordinator, Executor, Researcher and Reviewer apply the same distinctions. |
| `Explain complete selected bytes separately from complete work; preserve finite cutoff/tail` without a shared final checkpoint | Final RF/REVIEW/RES returns and Coordinator integration/close capture follow relevant results/checks, before final owner delivery. Planning/open-cycle estimates are interim. `complete: true` attests only the entire selected source bound. |
| `Missing units and excluded measurements remain gaps` treated as one completeness count | Report expected/received units separately from selected source/revision/range and material omitted coverage. Receiving every file does not prove that every role's current measurement enters the total. |
| Economics delivery enumerated six report sections as the default presentation | Use the adaptable model in [the economics report template](../templates/economics.md): question, result/comparison basis, approximate resources with coverage, then supported action or limit. Expand detail only when it serves the decision. |

For an unavailable pre-extraction binding, record the actual producer and observation epoch,
known binding facts, exact missing facts and reasons, that extraction was not attempted, and
any last-good returned bytes/hash or their absence. The unchanged helper does not parse this
prose: the responsible Coordinator/analyst reads it beside numeric output. An unreadable or
missing return remains unresolved. Available capture remains owed, and an explicit measurement
deliverable or required product proof retains its actual blocking route.

The finite cutoff excludes final delivery, short subsequent exchanges and safe cleanup once;
substantive reopening needs a separately bounded continuation. Never relabel incomplete old
captures as complete, manufacture a failure attempt or replace unknown consumption with zero.
Verified covering successors and disjoint ranges retain the existing reconciliation rules.

The practical 5–7% tolerance guides decisions; it is not measured accuracy or a guaranteed band.
Preserve exact observations and round only presentation. Material gaps remain visible. Compare
work membership, scope/complexity, accepted quality, rework, model/effort, coverage and valuation
basis; AI consumption does not establish human effort or competence. A small uncertain difference
supports no confident ranking. Further collection needs a concrete decision it could change.

## 3. Install and adopt at a valid boundary

Install the connected economics README/template, conventions and Plan/Handoff/Research/Review/
Economics workflows from the same pinned source. Apply the existing adapter manifest to installed
command copies and preserve project-owned customizations. No numeric schema conversion, provider
decoder change, extra record type or new runtime check is required. Daily keeps its own cadence.

For active work, adopt at the next authorized workflow checkpoint after validating current
scope, route and authority. Use the existing role artifact for an actual binding gap and the
normal return signal for transfer; do not add a parallel message channel or approval ceremony.
Retain prior contributions, their original source bounds and dated reports. If an explicit
measurement deliverable or frozen requirement conflicts with the proposed disposition, resolve
that requirement through its existing decision route before the dependent act.

## 4. Verify the selected receiver

Check version/config/changelog/guide agreement and source/copy parity. Confirm that the installed
Full roles all distinguish pre-extraction binding gaps, actual attempted failure, optional nulls
and unresolved returns; required proof remains blocking. Verify that an estimate states its
cycle checkpoint, received versus selected coverage and excluded tail, and that its conclusion
matches the available comparison evidence. Run the receiving project's configured checks and
record actual scope and limits in its update receipt. These checks establish instruction and
integration consistency, not measured savings or provider-wide reliability.
