# Updating to TFW 3.5.0

FRATS & AGSK — Framework Refactoring, Explicit Coordination, and Antigravity Skill Migration.
This release introduces explicit task-local coordination contracts, transcript isolation, restored
Strategic Architect planning, and a compressed active workflow corpus (≤1,400 words per workflow).
The Antigravity adapter now uses the same `.agents/skills/tfw-{command}/SKILL.md` surface as Codex,
while the deprecated `.agents/workflows/` directory and the vestigial singular `.agent/` directory
are fully retired from the framework repository. Downstream projects must classify and relocate
any custom content before deleting these paths.

## 2. Retire `.agents/workflows/` and install skill-based commands

The Antigravity adapter now routes `/tfw-*` commands through `.agents/skills/tfw-{command}/SKILL.md`
instead of `.agents/workflows/tfw-{command}.md`. Both Antigravity and Codex share the same skills
surface. Install the target skills and rule before removing the old workflow copies.

**Step 1 — Install the new surface.** Copy the ten command skills from the target source
(`.tfw/adapters/codex/skills/tfw-{command}/SKILL.md`) to `.agents/skills/tfw-{command}/SKILL.md`.
Copy `.tfw/adapters/antigravity/tfw-rules.md.template` to `.agents/rules/tfw.md`. Verify byte
equality between installed copies and their sources.

**Step 2 — Remove owned workflow files.** Delete the following paths when their installed bytes
match an admitted predecessor from the framework:

- `.agents/workflows/tfw-plan.md`
- `.agents/workflows/tfw-research.md`
- `.agents/workflows/tfw-handoff.md`
- `.agents/workflows/tfw-review.md`
- `.agents/workflows/tfw-docs.md`
- `.agents/workflows/tfw-knowledge.md`
- `.agents/workflows/tfw-release.md`
- `.agents/workflows/tfw-update.md`
- `.agents/workflows/tfw-config.md`
- `.agents/workflows/tfw-init.md`

Remove the empty `.agents/workflows/` directory after all files are deleted. A missing, customized
or ambiguous member refuses the connected retirement; do not delete a project owner's custom
workflow merely because its path resembles the former TFW surface.

## 3. Classify and retire `.agent/` (singular)

The vestigial singular `.agent/` directory is no longer part of the framework. Before deleting it,
inspect its contents and classify every file:

| Content type | Action |
|---|---|
| Framework-owned TFW files (`rules/agents.md`, `rules/tfw.md`, any file byte-identical to a known framework version) | Safe to delete after verifying the plural `.agents/` equivalent exists |
| Custom user rules (project-specific rules not part of TFW) | Move to `.agents/rules/{name}.md` and verify loading |
| Custom user workflows (project-specific workflows) | Convert to skills: create `.agents/skills/{name}/SKILL.md` with YAML frontmatter (`name`, `description`) and the workflow body |
| Local notes, conventions, CI status files | Move to project `README.md`, `docs/`, or the appropriate documentation location |
| Empty directory or no `.agent/` present | No action needed |

After relocating all user content, delete the empty `.agent/` directory. If `.gitignore` contains
an `.agent/` entry, remove it as well.

**Do not delete `.agent/` without inspecting its contents.** A blind recursive delete risks losing
project-specific rules and notes that have no other copy.

## 4. Adopt explicit task coordination for continuing work

FRATS replaces implicit autonomy inference with an explicit five-field routing spine in task and phase `status.md`:

```yaml
coordinator_route: "codex:thread:local:{uuid}"     # or antigravity:thread:local:{uuid}
owner_gateway: "owner:{handle}"                    # or unassigned
dialogue: "tfw-gates-only"                         # or delegated grant
activation: "owner-only"                           # or delegated:{ref}
coordination_authority: ".tfw/workflows/plan.md"   # or governing HL/TS path
```

1. **Continuing tasks:** If an active task continues across the 3.5.0 boundary, update its `status.md` frontmatter to include all five routing fields. Total legacy absence remains readable in historical tasks; a partial or contradictory spine refuses activation.
2. **Transcript isolation:** No role may read, tail, resume, search, or reconstruct another active role's transcript, reasoning, tool output, or unreturned worktree. Coordination routes exclusively through durable artifacts, gate events, or addressed vertical status messages.
3. **Deterministic artifact names:** Use `TS__{ID}.md` for single-phase work, `TS__phase-{x}__{slug}.md` for phase work, and `__rev{N}` for formal revisions. Do not rename historical artifacts.
4. **Historical tasks:** Closed tasks, historical journals, approvals, `CL`/`AG`/`AT` labels, and older filenames remain valid and must not be retrofitted.

## 5. Verify and complete the update

The framework VERSION and both framework configuration copies must agree at `3.5.0`. The live
manifest contains exactly ten commands, with the Antigravity adapter targeting
`.agents/skills/tfw-{command}/SKILL.md`. The persistent Antigravity rule targets `.agents/rules/tfw.md`.

Verify these conditions:

1. No `.agent/` directory exists in the repository root.
2. No `.agents/workflows/` directory exists.
3. `.agents/rules/tfw.md` is byte-identical to `.tfw/adapters/antigravity/tfw-rules.md.template`.
4. All ten `.agents/skills/tfw-{command}/SKILL.md` files exist and are byte-identical to their
   sources in `.tfw/adapters/codex/skills/`.
5. The project's test suite passes.
6. Active tasks continuing under the new contract have valid five-field coordination routing.

Record the actual source, target commit, affected paths, preserved custom inputs and any refusal
in the update receipt, then render the outcome through `.tfw/templates/briefing.md`.

Full TFW is the selected scope. Light, Assisted, OTR, knowledge lifecycle and provider admission
are unchanged by this release.
