# Updating to TFW 3.7.1

This patch strengthens strategic planning before HL approval and admits checked Daily results to
the project's release route. It changes instructions, not task-state schemas, routing fields or
provider capabilities. Existing approvals and historical artifacts are not reopened by installation.

## 1. Pin the source and retain the complete route

Resolve published `v3.7.1` to its exact commit and verify VERSION `3.7.1`. Before publication, use
only an explicitly authorized full untagged commit SHA and label it untagged. Read the pinned
target's update workflow, changelog and every applicable guide before receiver writes.

| Installed version | Ordered remaining obligations |
|---|---|
| 3.7.0 | This guide |
| Every earlier supported version, including supported 1.x and 2.0.0 dirty tags | Follow its exact ordered route in [3.7.0](3.7.0.md), then this guide |
| 3.7.1 | Verify source identity, selected bytes and any unfinished update before an already-current return |
| 0.x, unknown/custom or contradictory provenance | Stop for a bounded migration decision; full init is not migration |

Read obligations in order; install the selected final payload once. Preserve receiver settings,
personal preferences, project purpose, tasks, frozen approvals, journals, knowledge and unrelated
work. Earlier guides retain their historical wording; this guide supplies the successors below.

## 2. Refresh the connected instructions

Refresh `.tfw/workflows/plan.md`, `.tfw/templates/HL.md`, `.tfw/workflows/release.md`,
`.tfw/templates/RELEASE.md` and the release entry source under `.tfw/adapters/codex/skills/`.
Synchronize affected installed command/skill copies through the pinned tooling manifest. Do not
install absent adapters or change the ten-command Full set. The manifest, briefing template and
Coordinator profiles retain their applicable pinned bytes.

The changed `.tfw/extensions/daily-task/SKILL.md` belongs to the separately classified Daily group.
Follow its pinned `installation.md` before writing that group; preserve selected local forms,
history and opt-in. A customized or ambiguous member refuses that group unchanged, not unrelated
Full updates. Dormant source is not opt-in. The Daily entry copies themselves are unchanged.

Set VERSION and both framework-config version fields to `3.7.1`, merging only framework-owned
keys and recording exact source provenance. Include the matching changelog and this guide.

unconditionally requires Full artifacts and the owner wants Daily releases, obtain authorization
for a small project-specific evidence-route amendment. A framework update alone grants neither
that policy change nor a release. Existing project-required review remains applicable.

## 4. Verify the selected result

Verify source/ref, VERSION, config versions, changelog and guide agree; affected installed copies
match their exact sources. Check preserved project settings, historical task bytes and Daily forms.
Inspect Full and Daily release routes: each retains its actual evidence, acceptance, required
review and separate external-effect authorization. Mixed releases must not relabel Full work Daily.
Run the receiver's configured checks and retain actual results and limits in its update receipt.
Upstream additionally runs configured pytest/MkDocs and staged/release-history Git-blob guards.
Source checks do not prove native agent behavior or successful checks in a receiving project.
