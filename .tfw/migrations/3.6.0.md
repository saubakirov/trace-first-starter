## 3. Adopt current selection without inventing a decision

The prior status rule said: “Current writers emit and strictly validate all five.” The successor is
the complete seven-field current form: the existing `coordinator_route`, `owner_gateway`, `dialogue`,
`activation`, `coordination_authority`, plus `reporting` and `selection_ref`.

1. Existing five-field records remain readable with their actual authority and native-gates
   compatibility. Do not infer new delegation, dialogue or owner-transfer from their age or default.
2. Before a current write, verify the real original human selection, immutable governing source and
   lineage. Only then migrate the complete old form truthfully with `reporting: native-gates` and
   `selection_ref: baseline` when that is the verified choice. This migration is not a lifecycle
   transition and emits no same-state event. Preserve immutable historical events unchanged.
3. Total absence of routing fields remains legacy read-only, not current activation. Partial old or
   new forms refuse. An unavailable source blocks only the dependent new authority; historical
   readability is not converted into permission or destroyed.
4. An actual owner switch within the frozen HL ceiling uses one task-local `coordination_selected`
   event with source, old/new values, exact scope, roles, reservations and effect checkpoint. Commit
   that event before its SHA enters an effective `selection_ref`. Pending/future choice changes no
   live status before its condition is verified. State remains authoritative; no event-replay registry.
5. A phase reads its own status. Its only ancestor exception is a reference to the exact governing
   task's immutable selection event explicitly covering that phase/roles. Validate lineage and
   containment; sibling/foreign sources refuse. Do not poll root status continuously for permission.
6. Non-revoking changes preserve valid activation, units and pending gates. Revocation stops new
   delegated launches and returns active work at a safe boundary; failed notice remains an explicit
   open action, not a claimed remote halt. Frozen scope/authority changes still use HL amendment.

Manual role creation defaults to mandatory vertical native gates. Only the owner's explicit fully
manual `owner-transfer` selection disables inter-agent sends; it does not disable required artifacts.
No automatic bulk migration or historical rewrite is part of installing this release.

## 5. Preserve thinking, close and verification

Working Backwards, finished-result visualization in both chat and HL, visible consequential
hypotheses, constructive critique, Saint-Exupery judgment and planning-quality priority remain
mandatory. A startup card is not a substitute for strategic discussion or permission to skip HL/TS.
Preserve explicit owner acceptance where the governing task reserves actual Plan-text review.

Close includes actual docs/knowledge dispositions, independent assessment of changed final claims,
one truthful task changelog and safe disposition of exact task-owned resources after durable return
and result preservation. Archive is not proof of disk removal. Retain shared/sole-copy/unknown or
restoration-dependent resources honestly; pending required disposal prevents a fully cleaned claim.
Neither task close nor its changelog grants release, tag, push, publication or deployment authority.

Verify the exact prepared receiver composition:

1. VERSION and both framework-config versions agree at `3.6.0`; project-owned values are preserved.
2. Installed command copies/managed blocks agree with their selected sources; thin skills remain
   thin, no absent adapter is installed and only the selected runtime profile is loaded.
3. The early whole-arrangement card and later no-repeat selection are consistent. Command-only
   activation, late identity, independent topology/dialogue and the per-launch quality floor survive.
4. State readers and templates agree on legacy, complete old/current, partial, baseline, immediate,
   future-effective, revoked and exact-ancestor cases. Label synthetic checks; never create a dummy
   agent or an owner decision just to obtain a positive receipt.
5. Changed proof is checked; unrelated valid proof is reused. Existing task/journal/knowledge history
   and unselected work are unchanged by payload installation.
6. Run the receiving project's configured checks. Upstream uses
   `python -m pytest tools/tests/ docs/scripts/ -q`,
   `python -m mkdocs build --config-file docs/mkdocs.yml`, and the staged/full-history release Git-blob
   guards. These are upstream assurance, not mandatory receiver tooling or external-provider proof.
7. Record the pinned source, target commit, selected paths, preserved custom inputs, refusals and
   actual results in the update receipt; render the owner's outcome through the unchanged briefing
   template. Equal-version recovery still checks source identity and complete selected topology.
