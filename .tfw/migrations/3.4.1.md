# Updating to TFW 3.4.1

TFW 3.4.1 removes the separate `/tfw-resume` command. Use `/tfw-plan` for both new work and an
existing task or phase; planning resolves the recorded lifecycle and routes to the canonical next
workflow without creating a second continuation surface.

## 1. Pin the target and follow the complete route

Read the final target's update workflow, changelog and every applicable migration guide before
changing files. A published installation must resolve `v3.4.1`, its commit and matching VERSION.
An authorized untagged source uses its exact full SHA and never impersonates this release.

## 2. Refresh readers before retiring Resume

Install the target planning, init and update workflows and their owned adapter copies before removing
the old entry. Refresh the command manifest and generated receiver surfaces as one connected group.
Then remove these owned files when their installed bytes match an admitted predecessor:

- `.tfw/workflows/resume.md`;
- `.tfw/adapters/codex/skills/tfw-resume/SKILL.md`;
- `.agents/skills/tfw-resume/SKILL.md`;
- `.agents/workflows/tfw-resume.md`;
- `.claude/commands/tfw-resume.md`.

Remove the corresponding Resume registration from managed command inventories. A missing, customized,
mixed-version or ambiguous affected member refuses the connected retirement; do not delete a project
owner's custom continuation command merely because its path resembles the former TFW surface.

## 3. Replace the retired obligation

The retired skill described itself as: “Command /tfw-resume locates and resumes a Trace-First Workflow
task from filesystem traces and its own task state.” The successor is `/tfw-plan`: when given an exact
existing reference it reads that task or phase's status and journal, preserves its authority and AT
mandate, and routes to research, execution, review or Coordinator-owned closing as the state requires.

Do not add an alias or replacement Resume workflow. Historical artifacts may continue to mention
`/tfw-resume`; they are evidence of their original epoch, not live command registrations.

## 4. Complete the update

The framework VERSION and both framework configuration copies must agree at `3.4.1`. The live manifest
contains exactly ten commands and no Resume entry. Existing task/phase status, journals and historical
containers remain byte-preserved unless a separate authority governs them. Record the actual source,
target commit, affected paths, preserved custom inputs and any refusal in the update receipt, then render
the outcome through `.tfw/templates/briefing.md`.

Full TFW is the selected scope. Light, Assisted, OTR, knowledge lifecycle and provider admission are
unchanged by this patch release.
