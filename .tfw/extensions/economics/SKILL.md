# TFW Economics

**Mindset:** Connect intended and achieved work to observed resources, then explain the decision
the reader can make. Tokens, money equivalents, time and product benefit answer different questions.
Adapt depth to the request and available grounds; a small report can be complete. No quota of
anomalies, charts or recommendations justifies invented content.

**Authority:** This optional analytical skill reads authorized work records and returned numeric
contributions. It grants no formal role, lifecycle, acceptance, deployment or foreign-source access.
An existing Full role keeps its Role Lock and vertical reporting route. Ordinary owner-directed
analysis replies in chat. Read no other unit's native sessions or unreturned working state.

## 1. Resolve the question and evidence

Read the request and applicable receiving rules/preferences. Select only the necessary current
task/phase status, HL and returned RF/REVIEW or the explicitly selected Daily record and product
result. State source epochs, intended value, actual achieved/accepted state and their uncertainty.
Accepted, prepared, checked and released are distinct. Do not infer success from resource totals.

Resolve task/phase, project, day/month/date range, owner, roles/units/models or product interest
against available facts. Give exact root/work membership and inclusion/exclusion reasons. A question
about period spending selects evidenced consumption dates; a task-event cohort selects evidenced
created/completed events and then lifetime usage, including undated rows. Cutoff, generic update,
current state and folder date never manufacture consumption/completion dates. If ambiguity changes
membership or totals, ask one focused clarification and continue independent supported analysis.

Read `.tfw/economics/README.md` at the selected receiving root before numerical operations. Validate
existing returned bytes and reconcile revisions/source ranges once with its helper or a checked
equivalent. Record exact returned file hashes and selected/excluded membership. Never add parent
reports, cumulative snapshots, chart/CSV views or overlapping filtered subtotals to their facts.
Unknown usage remains unknown; an empty accepted sum is not evidence of measured zero.

For Daily, use its actual selected record through `--record`; retain compatible local forms.
Unknown required binding is a nonmeasured record-local outcome, visible with actual producer,
known facts, unavailable reasons, extraction-attempt state and last-good bytes. Bound extraction
failures retain v1 failure receipts. Show the latest exact cause and unmeasured attempted interval
even when a previous good snapshot exists; a failed attempt cannot erase useful measurement.

The reporter consumes received authorized bytes, not an inaccessible producer pathname. Missing
units and excluded measurements remain gaps. Explain complete selected bytes separately from
complete work; preserve finite cutoff/tail and incompatible duration kinds. Dated local Standard
API equivalents use the pinned rate epoch, never subscription invoices or invented current prices.

## 2. Connect product meaning and inspect useful comparisons

Preserve native primary area and keywords. With cited work/result grounds, distinguish domain,
subject area, feature, user scenario and delivery context. Label derived classifications and their
sources. A shared ontology is unnecessary. One primary area is additive; overlapping interests
select a deduplicated union of associated tasks. Without attributable feature records, name
associated-task resources, never feature cost. Keep project/work/root/phase context distinct when
different projects share a task ID.

Calculate only dimensions that explain the question: resource concentration, role/unit/model
mix, fresh/cache/write/output mix, supported date changes, iterations or scope changes, accepted
contributions and comparable tasks. Retain denominators, units, selections and checked arithmetic.
Use temporary checked calculations when the existing helper has no direct selector; explain an
unavailable dimension rather than guessing. Task cohorts require separately cited event membership.

Separate an observed fact from interpretation, causal hypothesis and next check. A statistical
outlier requires a named comparable baseline and method. A single-task unusual fact can be an
observation. Observed concentration or expense does not prove waste, efficiency, quality or savings.
Describe benefit through accepted outputs; ROI, prevented loss and quality rankings require
independent measurement. Collector operation time, invocation/integration wall time and native
agent/model duration remain separate; never add internal collector time again to invocation time.

## 3. Deliver an executive opening with inspectable detail

Default is chat in the user's language. Use `.tfw/templates/economics.md` as the report mental model:

1. **Executive summary:** question, achieved result, supported economic conclusion and decision.
2. **Product map:** sourced domains/areas/features/scenarios and what their association means.
3. **Numerical detail:** unique membership, token/money/time distributions and useful comparisons.
4. **Material observations:** evidence, interpretation, causal uncertainty and next verification.
5. **TFW improvements:** actionable proposals grounded in observed context, iteration, scope,
   handoff, collection or checking costs. Name the affected mechanism and next authority/check.
   Explicitly say when no grounded improvement is warranted.
6. **Coverage and sources:** epochs/hashes, selected/excluded contributors, unpriced/undated/unknown
   values, latest failures, limits and finite cutoff/tail.

Prose and Markdown tables carry the entire answer. Supplementary visuals are useful only when
requested or they clarify a supported comparison and the selected host actually renders them.
Never promise graphics from source presence or filesystem parity. PDF is request-only: verify an
absolute OS-temp path outside the repository before producing it, use an available renderer and
inspect the result. If unavailable, return the complete text/table report and precise renderer gap.
Ad hoc analysis/render scripts also stay in OS temp; ship no permanent analytical/render script suite.

Record selection, commands/oracles, source/rate epochs and material limitations in the existing
authorized trace when owed. Temporary views are derived, not a second portfolio authority. Return
through the active role's Coordinator if applicable; never accept a result or continue into another
formal role through this analytical skill.
