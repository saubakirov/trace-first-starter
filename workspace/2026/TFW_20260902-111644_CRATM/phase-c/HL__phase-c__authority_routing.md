## 3. Target State (To-Be) — derived from master §3 items 7–8

1. An initiation edge is the existing task/phase-local `dispatch` fact: Phase B's `writer` names the
   initiating principal, the dispatch names its destination, and its references identify the
   governing scope/role artifact. The event indexes semantic evidence; it is not a transcript or a
   new registry.
2. The human root and terminal human ruler are the declared human `owner` from the governing task or
   phase `status.md`. A separate governing record must show that this owner authorized the root
   Coordinator; `accountable_to` proves only profile accountability and cannot create that prefix.
   A new child edge may be appended only by a Coordinator already on one unambiguous authorized
   prefix, and only toward a child not already on it. An Executor initiates nobody; a phase
   Coordinator cannot point to the task Coordinator or any ancestor. Missing, competing, backward,
   unassigned-owner, or non-human-terminating delegated provenance refuses the delegated work.
3. The proposer is the principal that originated the proposed frozen change. A Coordinator who
   transcribes another role's row into §12 does not become its proposer. Session replacement does not
   replace principal identity.
4. For an ordinary `EXTEND` or `SUPERSEDE`, walk from the proposer toward that status-owned human
   root. The first
   principal with immutable `may_rule_amendments: true` that is not the proposer rules. Skip false
   grants and the proposer; if no eligible agent remains, the governing `status.md` owner rules.
5. A §12 terminal verdict names the resolved ruler principal. The Coordinator validates chain,
   proposer, grant, reservation, and signature before applying a frozen change and re-freezing.
   Unresolved or ambiguous authority is a hard stop, never an owner guess or Executor decision.
6. Human-reserved paths do not become ordinary delegated amendments: an owner-reserved claim and an
   agent principal's own grant/change-of-handle decision route to the owner; Purpose Check contract
   defect/not-fit and `❌ REJECT` stay with the owner; budget authority and unavailable participants
   keep their governing routes. `RESTRICT` still applies on filing without a verdict.
7. An owner-initiated frozen change remains the existing direct human amendment only when it records
   the human owner's real explicit decision: the same row records `Proposer = owner` and that
   already-authoritative act. An agent's `on_behalf_of`, human binding, or `accountable_to` never
   creates this exception and never authorizes an agent-proposed self-ruling.
8. A normal CL task with no declared delegated chain keeps its direct owner-only amendment route. The
   refusal above applies when delegated authority is claimed but its chain is absent, ambiguous, or
   contradictory; Phase C does not make existing non-delegated tasks unexecutable.

### 3.1 Result Visualization

```text
governing status.md owner (human) + separately recorded root authorization
└─ root Coordinator: ruler-a (grant=true)
   ├─ Researcher: probe-b (grant=false) ── proposes A1
   │  └─ proposer preserved as probe-b
   │     walk upward → ruler-a (true, not proposer) → may rule A1
   └─ Phase Coordinator: ruler-c (grant=true) ── proposes A2
      └─ same principal in a fresh session is still ruler-c
         walk upward → ruler-a; if reserved/self-grant → human owner

REFUSE before work:
executor ─X→ child       child ─X→ ancestor       unknown/ambiguous prefix ─X→ dispatch
```

| Case | Ruler / outcome | Guardrail fixture |
|---|---|---|
| Child proposer, nearest parent grant `true` | Parent principal | Positive nearest-ruler traversal |
| Parent grant `false`, higher grant `true` | Higher principal | False grant is skipped |
| Nearest eligible principal is proposer | Next eligible ancestor or owner | Same handle across two sessions still self-approval |
| Coordinator transcribes child's proposal | Proposer remains child; eligible Coordinator may rule | Writer/transcriber is not proposal originator |
| Owner-reserved claim | Owner | Reservation cannot be delegated |
| Agent changes its own grant / replacement handle | Owner | Identity cannot widen its own authority |
| Owner-initiated amendment | Real explicit human owner's recorded act | `on_behalf_of`, binding, or accountability cannot impersonate the owner |
| `RESTRICT` | Applies on filing | No synthetic verdict is created |
| Purpose Check defect/not-fit or `❌ REJECT` | Owner | Review's human return stays literal |
| No delegated chain is declared (ordinary CL) | Direct owner-only route | Backward compatibility, not a chain defect |
| Profile has `accountable_to`, but no owner-authorized root prefix | Refuse delegated route | Accountability is not authority |
| Executor initiates, backward edge, missing/ambiguous/unassigned/non-human root | Refuse delegated route | No cycle, fallback, or guessed chain |

### 3.2 Value Flow

`stable writer → child-only dispatch provenance → preserved proposer → nearest eligible non-proposer
→ signed terminal verdict → re-freeze`.

Value is fewer routine owner interruptions without losing the direct human path for strategic,
self-grant, contract-defect, rejection, malformed-chain, and reserved-claim decisions.
