### C3 — A generic protobuf fingerprint is the wrong abstraction

[Official Protocol Buffers guidance](https://protobuf.dev/programming-guides/serialization-not-canonical/), checked 2026-10-27, explains that serialized bytes are not canonical and advises a deliberately specified field selection when a semantic fingerprint is needed. This supports caution, not an explanation invented for the native observation: Extract saw actual nonnumeric field changes and a large size reduction, not merely a different field order.

A whole-database file hash is an even broader observation, not proof of equality of selected numerical rows. [SQLite's backup documentation](https://sqlite.org/backup.html) supports a consistent snapshot for a single read; it does not promise that a later native resume preserves the same bytes. Keeping the existing read-only backup technique is compatible with either C7 or C8.

C7 would require explicit measured fields, inclusion semantics, normalization, null/zero treatment, model identity, range/event identity and an old-receipt transition. An unchanged schema number would not by itself preserve the meaning of an old raw-prefix hash. That extra contract is unnecessary while C8 remains a feasible existing route. No numeric history should be rewritten to retrofit a new digest basis.
