## Findings

### C1 — Exit and nonprogress do not need a second controller

| Attack | M11 response | Limit / consequence |
|---|---|---|
| Assistant says complete, shell exits zero or a loop reaches its cap while criteria remain unmet | Preserve the actual execution outcome; RF/EV claims still require independent review and applicable owner acceptance | No inferred success or phase advancement |
| Same failure returns with the same remedy and no changed evidence | Coordinator diagnoses the actual missing basis at the existing return/ruling; E may propose a discriminating action within scope | No automatic stronger model, new round counter or blind redispatch |
| A transient tool error has an obvious bounded retry within approved work | Executor performs the authorized retry and records material outcome in normal evidence/return | No owner question for every command or failed attempt; all actual invocation costs remain attributable |
| Failure reveals a changed specification or frozen premise | Apply the existing TS or frozen-HL route for that material item | Highest required authority sequences the next act; it does not convert every finding or unchanged Candidate into new work |
| No complete material completion condition can be stated | Use existing approve/dispose or BLOCKED handling with the missing basis and resolver | Repetition is not evidence and cannot manufacture a finding |
| Cancellation, missing authority or unavailable capability interrupts work | Stop the affected act, preserve available partial result and exact pending condition | No hook may override the stop; unrelated authorized work need not be reopened or stopped without a dependency |

External counterexample: the official [Stop hook pinned at `986deab6…`](https://github.com/anthropics/claude-plugins-official/blob/986deab6a1659ebb998b66962df6f02b20bb884d/plugins/ralph-loop/hooks/stop-hook.sh) allows exit after the iteration cap, corrupt numeric state or missing transcript, and separately after a matching assistant promise. Otherwise it repeats the prompt in the same session. These source paths demonstrate why a successful hook/process exit cannot be used as an acceptance oracle. The code was inspected, not executed. Its session guard does not prove isolated parallel loop state or reliable interruption in our surface.

M11 does not promise optimal retry decisions. It supplies an inspectable decision point: a changed basis or bounded diagnostic can justify another authorized act; unchanged failure without such a basis cannot justify mechanically repeating it. Ordinary work does not need a new form. Material decisions fit the existing ONB/RF/REVIEW/ruling and handover sections. Actual nonprogress without a reliable observation must remain uncertainty, not an invented diagnosis.

### C2 — Freshness cannot be traded away by its beneficiary

| Attack | Required result |
|---|---|
| Coordinator calls R1 a default and reuses R despite a phase TS saying fresh R is mandatory | Refuse the local exception. The harder scoped requirement controls until validly changed by its actual ruler |
| A parent planning grant is read as permission to override phase freshness | Verify actual discretion and reservations; parenthood or title supplies none. Missing grant blocks reuse, not all planning |
| Reviewer volunteers that it can be objective, or Executor requests the familiar Reviewer | Neither can authorize the exception. Their information may support the authorized Coordinator's decision but does not grant it |
| New Reviewer is forked from Executor context or participated in prohibited design/consolidation work | Fresh identity does not establish independence. Reject this Reviewer assignment even when capacity is scarce |
| Same-phase correction or TS revision is relabeled as a new phase to discard an unfavorable review | Actual governed scope/authority and history determine the phase. Preserve the live finding/ruling and same E/R unless a valid replacement is needed |
| Phase B reuses independent R under explicit discretion, then A correction arrives | Preserve both states and routes; no concurrent conflicting activation. Serialize and revalidate the affected scope or authorize an actual replacement. Previous A identity is not a standing B mandate |
| E changes VALUE after R inspected the Candidate | Fix a new Candidate and independently check the affected return; context continuity does not preserve an obsolete approval |

Fresh B Reviewer may read accepted A artifacts needed for dependencies. That is distinct from inheriting A's private review conversation or Executor reasoning. A prior reviewed assumption contradicted by B's evidence must be judged against B's approved criteria, regardless of whether R is fresh or validly reused. The default reduces one path for inherited assumptions; it does not prove their absence or replace independent judgment.

The exception therefore survives only as a bounded exercise of already granted discretion. Explicit mandatory freshness and independence are not waivable by that exception. If policy changes are needed, ordinary existing authority routes apply; this is not a routine new approval gate.

### C3 — The real capability dead end remains honestly nonterminal

Consider phase B whose governing authority requires fresh independent R. Available native operations cannot create a new context, or the actual creation attempt returns unavailable/capacity failure. A retained R conversation, title change, interruption, wait, archive or completion is not proof of fresh context or released capacity. This surface exposes no close-agent operation. The advertised concurrent-slot count does not establish a retained-ID lifetime limit. This scenario was reasoned from the current tool contract; no new role launch or capacity experiment was performed.

The exact pending condition is **an available, authorized mechanism that can provision and address a genuinely fresh independent Reviewer for B, with its actual receipt, B authority/source binding and fixed reachable Candidate**. The existing phase-responsible Coordinator owns resolution and the bounded return upward. It preserves Candidate and prior returns; it does not declare review complete. If absent review blocks phase acceptance, that acceptance remains nonterminal under the existing blocked/dependency route.

| Actual available resolution | Who acts and what must change | Forbidden inference |
|---|---|---|
| Capability becomes available under the already approved arrangement | Coordinator uses the supported mechanism, verifies the actual receipt/context and activates B review | Elapsed time or an unchanged signal is not recovery; no rapid retry loop |
| An already authorized alternate mechanism really supplies fresh independent context | Coordinator uses it within the existing grant and validates actual routing, source, workspace and Candidate access | No hidden helper, unauthorized provider switch or relabeled retained context |
| A different arrangement needs new authority | Coordinator returns the exact missing arrangement decision to its actual resolver through the existing route | Do not ask the owner to approve every ordinary continuation thereafter |
| Freshness is a permitted default, no harder requirement applies, and explicit exception discretion exists | Coordinator may assess bounded R reuse with concrete reason and all receiving checks | Capacity failure alone supplies neither discretion nor independence |
| Freshness is mandatory and no supported fresh-context mechanism is available | Preserve the block. If warranted, propose a specific policy/surface change to its legitimate ruler; otherwise await the exact capability condition | No automatic reuse, fictional slot release, invented API or acceptance without review |

This is a genuine liveness limit, not a contradiction in M11's safety/authority contract. It prevents a promise of unattended completion on every host. A single bounded return can name a pending capability or actual decision; it need not establish a perpetual owner-mediated dispatch gate. The Coordinator can resume autonomously once the approved capability condition is evidenced, with ordinary receiving checks.
