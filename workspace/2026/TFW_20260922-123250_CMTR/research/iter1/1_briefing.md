## Research Plan

### Gather
- Инвентаризировать актуальные параметры выбора моделей и настройки thinking/reasoning в трех целевых средах для полноценных сессий: Google Antigravity (UI селекторы, пресеты thinking), OpenAI Codex (UI dropdown, native task parameters: model, reasoning_effort), Claude Code / Desktop (UI dropdown, CLI parameters: `--model`, `--max-thinking-tokens`).
- Изучить текущие шаблоны и воркфлоу TFW (`plan.md` Step 5, `HL.md §4.1`, `TS.md`, `conventions.md §7`) на предмет точек интеграции когнитивных рекомендаций.
- Собрать внешние данные и эмпирические наблюдения по влиянию силы thinking на разные типы задач (рутина vs стандартная реализация vs архитектурный/состязательный анализ).

### Extract
- Сформулировать минимальную систему классификации задач — правило 3 уровней:
  1. Procedural / Routine (рутинные правки, документация, синхронизация конфигураций).
  2. Standard / Implementation (инженерная реализация по четко специфицированному TS).
  3. Critical / Adversarial (концептуальное проектирование HL, состязательное ревью, глубокое исследование).
- Построить матрицу соответствия 3 уровней нативным параметрам каждой платформы (Antigravity, Codex, Claude Code).
- Сформулировать правила самокалибровки координатора (эвристики детекции нехватки когнитивной мощности или избыточного оверхеда в текущей сессии).
- Разработать лаконичный формат рекомендации координатора для ручного запуска в UI (для человека) и автономного создания сессий (для платформ с API).

### Challenge
- Проверить жизнеспособность правила 3 уровней на пограничных случаях:
  - Когда процедурная задача скрывает под собой архитектурный дефект (риск занижения мощности).
  - Когда избыточный thinking приводит к зацикливанию, переусложнению или галлюцинациям на тривиальном коде.
  - Когда у пользователя в интерфейсе отсутствует рекомендованная модель конкретного провайдера (принцип fallback/универсальности уровней).
- Проверить соответствие принципам TFW: F25 («фреймворк предлагает — человек выбирает»), F43 (качество архитектуры, а не фиксы), F45 (вычитание лишних сущностей), D59 (разграничение границ возможностей).
- Зафиксировать открытые вопросы для итерации 2 (состязательное испытание на контрастных исторических кейсах TFW).
