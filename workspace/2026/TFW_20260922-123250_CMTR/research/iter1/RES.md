## Research Context

Первая итерация исследования задачи CMTR выполнила инвентаризацию параметров моделей и режимов reasoning/thinking в целевых средах TFW (Google Antigravity, OpenAI Codex, Claude Code) для полноценных сессий (окон/чатов). На основе анализа размерностей когнитивной нагрузки и механизмов запуска сформировано устойчивое «правило 3 уровней сложности» (Procedural, Standard, Critical), механизм дуального запуска сессий (UI-подсказка vs автономный API-запуск) и правила ненавязчивой самокалибровки координатора в активном окне. Все решения спроектированы в соответствии с принципом Сент-Экзюпери (F43, F45) как минимальные расширения существующего контракта координации без создания новых сущностей и файлов.

## Briefing

Исследование следовало плану [1_briefing.md](1_briefing.md). Фокус итерации: инвентаризация параметров сред, формулирование эвристик классификации и самокалибровки, определение минимальных мест расширения ядра TFW. Состязательное испытание на сценариях зарезервировано для итерации 2.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Принять 3 дискретных класса когнитивной сложности: **Procedural**, **Standard**, **Critical** | Бинарная шкала недостаточна (смешивает архитектуру и код), а 5 уровней или непрерывный математический скоринг раздувают когнитивный оверхед человека. 3 уровня покрывают 95%+ сценариев TFW. |
| D2 | Использовать дуальный механизм запуска: компактная подсказка для селектора UI человека по умолчанию + автономная передача параметров при подтвержденном API создания независимых сессий | Учитывает границы возможностей сред (D59): Antigravity и Claude Desktop требуют запуска человеком через UI, в то время как Codex native tasks поддерживают программное создание тредов. |
| D3 | Интегрировать параметры когнитивного профиля непосредственно в существующие контракты (`plan.md` Шаг 5, `HL.md §4.1`, шапка `TS.md`, `conventions.md §7`) | Предотвращает появление параллельных файлов конфигурации (`models.yaml`), защищает ядро от засорения (F43, F45). |
| D4 | Реализовать самокалибровку координатора через разовые рекомендательные сигналы (Up-Shift и Down-Shift) без блокировки сессии | Предотвращает архитектурный брак при работе координатора на слабых моделях, сохраняя свободу выбора за человеком (F25). |
| D5 | Использовать двухуровневый формат выдачи рекомендаций: абстрактный класс мощности + примеры моделей платформы | Защищает ядро фреймворка от устаревания коммерческих версий моделей и обеспечивает бесшовный fallback при отсутствии конкретной модели в подписке. |
