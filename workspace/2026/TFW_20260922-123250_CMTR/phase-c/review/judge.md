### Purpose Check

**Contract baseline.** The frozen master HL sections §1, §3–§7 are byte-content equivalent between
the re-frozen baseline `addb2e707dd9f271b7bf1287617a8b93b8d72cb0` and the reviewed source (the
only §7 difference in the whole file is the permitted free §7.2 area). Project North Star files are
unchanged from that baseline.

**Clause served and harm protected.** Master HL §1 requires that before each separate role unit the
Coordinator choose a sufficient model and reasoning depth for the exact next work, with the quality
floor derived from uncertainty, dependencies, external verification and error consequence, and says
the decision must act “непосредственно при запуске отдельной ролевой единицы.” The delivered rule
does that at Plan dispatch instead of storing a role/phase profile. It protects the concrete harms of
an under-capable launch losing purpose/authority/evidence and a default-max or decorative choice
wasting tokens, quota and sessions without evidence of benefit.

NS1 says work that increases output while obscuring purpose, authority, inspectability or
continuation is contrary to the North Star. NS2 requires purpose before activity, the simplest
complete form, human authority with bounded delegation and assurance proportional to risk; NS3 bars
vendor binding, documentation bureaucracy and untested capability claims. The result preserves
authority/return prerequisites and evidence limits in ordinary provider-neutral files, uses the
short accepted `Launch selection` name and removes two decorative template fields rather than adding
another artifact or provider table.

1. **Excess and adjacency:** No adjacent adapter, glossary, configuration, roster, pricing, release,
   test or history work entered the accepted result. Exactly the owner-accepted four core files changed.
2. **Deferral confession:** Effective backend settings, empirical minimum/cost, savings and foreign-
   provider working routes remain explicitly unproved. The result does not ship those deferred
   questions as claims; it only encodes the rule that bounds them.
3. **Materiality:** No wording or structural issue found in Verify would materially weaken the
   approved quality floor, economy, authority, evidence honesty or continuation.

**Outcome:** ✅ Aligned. The reference set is coherent; the implementation is neither an adjacent
feature nor a formally correct substitute for the requested per-launch behavior.
