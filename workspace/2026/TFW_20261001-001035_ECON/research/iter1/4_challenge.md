A receiving implementation must verify the corrected contextual association as well as numerical totals; a correct total alone would miss this defect.

### C4 — External counter-evidence does not justify missing-date substitution

[OpenTelemetry Logs Data Model, Timestamp and ObservedTimestamp](https://opentelemetry.io/docs/specs/otel/logs/data-model/) distinguishes event-source time from collection-system observation time. It also recommends an observation-time fallback for some single-timestamp log conversions. That fallback is valid in that specification's conversion context; applying it as TFW consumption time would contradict this task's explicit date/source requirement. This counterexample reinforces why a generic last update/capture clock must not silently enter consumption-period selection. OpenTelemetry's `ObservedTimestamp` is not asserted to have the same meaning as TFW's `observed_at`.

[JSON Schema null reference](https://json-schema.org/understanding-json-schema/reference/null) supports preserving null distinctly from absence/zero; [W3C PROV-DM revision/attribution concepts](https://www.w3.org/TR/prov-dm/) support preserving source-derived versions and responsible producer context without replacing authority. These primary sources were accessed 2026-10-01. No OpenTelemetry dependency, PROV service, foreign source access or broader ontology is proposed.
