### The finding — D1, judge row 9

`review.md`'s new search block uses the awk field reference `$0`, twice. `$0` is also Claude Code's
slash-command argument placeholder. Invoked as `/tfw-review <path>`, the harness substitutes **before** the
workflow text reaches the agent, and this is what actually arrived in this review session:

```awk
s && /^\| / && workspace2026TFW_20260830-194027_TLDRF__TFW_20260830-194027_TLD.md !~ /^\| *(#|-)/ {print FILENAME": "workspace2026TFW_20260830-194027_TLDRF__TFW_20260830-194027_TLD.md}
```

Both occurrences replaced by the argument with its separators stripped. Invoked bare, `$0` resolves empty
and the awk program is a syntax error instead. **Either way, every Claude Code invocation of `/tfw-review`
delivers a search that cannot run** — and it fails in the worst way, by still looking like a shell command.

Why this is not a small thing. TS AC-3 requires the operation *"written out literally, so a reader can run
it without inventing it"*, and HL DoF 5 fails the task if *"the canon states no operation by which open
items can be listed"*. The canon states it correctly and the primary adapter mangles it on delivery. This
is the release's headline mechanism — the thing that replaces a maintained registry with one search —
failing at the point of use, in the first review conducted under the new rule.

**What is not wrong, and should be said plainly.** `cmp` fidelity is perfect and AC-10 is met exactly as
written: the copy *is* byte-identical to its source. Nothing in the canon warns that `$N` collides with an
adapter's placeholder syntax, and no workflow at the baseline carried a numeric `$N` — the pre-existing
snippets in `config.md` and `update.md` use named variables the mechanism does not touch. This is a new
hazard, not a missed rule. But the RF's own §8 S3 makes the argument that catches it: *"when discovery
replaces maintenance, the discovery key becomes an interface."* The same reasoning, one layer down at the
transport, is the finding.

**Routing:** back to the **executor**. This is a work defect inside approved TS scope (AC-3 and AC-10), not
a purpose failure and not a contract defect. The Purpose Check passes: the design serves HL §1 and `NS3`
exactly, and the fix is one line.

### Items to fix

1. **Remove `$0` from the search block in `.tfw/workflows/review.md`, then re-sync and re-`cmp` the two
   adapter copies.** The operation's behaviour must not change and it must still return 243 on this corpus.
   Any formulation that avoids a bare `$N` will do — for example matching the row shape positionally, or
   binding the record to a named variable first (`{ln = $0}`) and testing `ln`. The choice is the
   executor's; the requirement is that what a Claude Code reviewer receives is what a reader can run.
2. **State the hazard where the next author will hit it.** One sentence, in the file the executor judges
   right — `conventions.md` §11 Design Rules is the natural home: a shell snippet in a workflow must not
   use `$0`–`$9` or `$ARGUMENTS`, because adapter harnesses substitute them before the text is read. This
   is the structural half; without it the same defect returns the next time anyone writes a command into a
   workflow.
3. **Re-verify and re-record**, in an `RF__…__rev2` or an amended §4: the search re-run returning 243, and
   the adapter copies re-`cmp`'d.

Nothing else is owed. The CHANGELOG, `VERSION`, the snapshot, the migration step, the census and the
evidence all stand as written; a `2.1.1` line in the CHANGELOG naming this fix is the coordinator's call at
release, not the executor's here.

**On the arithmetic slips (D2–D5):** none is a fix. Three sit in the RF and EV, which are historical traces
and are not edited after the fact; the fourth is in the coordinator's own HL §2. All four are disposed of
in §5 below.
