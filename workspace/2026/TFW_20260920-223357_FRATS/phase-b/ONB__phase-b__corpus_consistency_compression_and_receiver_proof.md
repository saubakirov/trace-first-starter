## 4. Recommendations (suggestions, not blocking)

1. Build the source→reader→delivery census and successor measurement before editing. This makes
   every subtraction auditable and permits a zero-diff disposition where a listed path is already
   canonical.
2. Keep the historical audit and current successor metric as task-local evidence. Neither has a
   named runtime reader that would justify restoring or adding a maintained production tool.
3. Consolidate shared semantics into conventions, keep workflows algorithmic, templates structural,
   and adapters provider-specific. Preserve local repetition only when recovery without another
   available source is part of an actual reader path.
4. Change canonical workflows first and regenerate Claude/Antigravity copies byte-for-byte. Never
   hand-edit a generated projection into an independent implementation.
5. Capture each receiver's HEAD, branch and worktree state before and after inspection. If a receiver
   moves independently, record a separate epoch rather than merging observations.

   `workspace/2026/TFW_20260921-180000_RVAG/`. Exact-path staging is mandatory so none enters a
   FRATS commit.
2. The baseline precedes Phase A while the worktree begins at the later Phase B approval commit.
   Baseline→Candidate VALUE accounting must therefore distinguish Phase A changes from Phase B
   implementation and use the literal selector exactly as approved.
3. The historical audit's selector is not the current ten-command reader selector. Similar-looking
   totals are not a series unless the bridge, exclusions and deduplication rules are stated.
4. Compression can accidentally convert a recoverable provider entry surface into a pointer whose
   target is unavailable to that reader. Such repetition must remain and be justified in the ledger.
5. `docs/scripts/command_entry_eval.py` contains synthetic fixtures for the Phase A contract. It may
   change only where Phase B changes a production contract actually read by those fixtures; no new
   permanent test is authorized merely to satisfy evidence coverage.
6. Receiver repositories may contain local customizations or older installations. Their state is
   bounded evidence, not authority to generalize a universal migration claim.
