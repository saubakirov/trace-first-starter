## 4. Recommendations (suggestions, not blocking)

1. **Codex sandbox (AC-2).** The owner can observe it with one PowerShell line in a Codex session; the
   Coordinator may route it now so the result can arrive before RF. It fetches `v3.7.1` into the
   session's temp folder, prints the size and the number of raw-byte mismatches, and deletes the
   folder; it changes no configuration:

   ```powershell
   $d = Join-Path $env:TEMP 'lfd-codex-probe'; git clone -c core.autocrlf=false -c core.attributesFile= --filter=blob:none --sparse --depth 1 --branch v3.7.1 https://github.com/saubakirov/trace-first-starter $d; git -C $d sparse-checkout set .tfw; git -C $d count-objects -vH; $bad = 0; git -C $d ls-tree -r HEAD -- .tfw | ForEach-Object { $f = $_ -split "`t"; $id = ($f[0] -split ' ')[2]; if ((git -C $d hash-object --no-filters -- $f[1]) -ne $id) { $bad++ } }; "mismatches: $bad"; Remove-Item -Recurse -Force $d
   ```

   The Executor runs the same line in Windows PowerShell 5.1 before relying on it. Without the owner's
   result by RF, the sandbox is reported unavailable with that reason.
2. **Fallback without a whole-tree checkout.** When Git rejects an option, repeat the clone with
   `--no-checkout` in place of the filter and sparse options, then check out only `.tfw`. This still
   meets AC-1's "without filter and sparse options" and avoids writing the tag's whole 313.7 MiB tree
   and its long paths into staging.
3. **Install prompts defer the copy to `quickstart.md`.** Both prompts now say "copy .tfw/ and follow
   .tfw/quickstart.md"; a literal copy would carry the upstream's `project_config.yaml`,
   `knowledge_state.yaml` and `update_receipts/` into the receiver (F23). The new prompts fetch, then let
   `quickstart.md` Step 1 make the copy with its existing exclusions, which AC-4 and DoD 4 need.
4. **A fresh staging area.** State that `.tfw/.upstream/` must be absent before the fetch, so a
   leftover from an earlier attempt cannot pass stale files into the Step 3 copy; the per-path check
   lists only pinned paths and cannot see extra ones.
5. **Accounting shown against both Baselines** (see §6, item 1).

## 5. Risks Found (edge cases, potential issues not in TS)

1. **Economics collision for Claude Code subagents.** The helper requires a Claude source ID equal to
   the transcript's `sessionId`; a subagent transcript carries its parent session's ID, and receive
   groups files by `(namespace, source_id)` and compares line ranges numerically. The Coordinator's own
   capture and this Executor's could therefore be excluded as "overlapping" although they are different
   files. Outside this task's VALUE scope; the Executor still returns its measured file and states the
   limitation in RF.
2. **The trial update is synthetic.** It uses a scratch receiver installed light from `v3.7.1` with the
   Claude Code adapter, the Candidate's `update.md` installed, and the Candidate as an authorized
   untagged target from a local file-protocol mirror that allows filters. Its times are this machine's
   and this connection's; a real receiver's customizations are not exercised.
3. **The first update after release still runs the old installed Step 0** (HL §9). The README hint
   carries the light-fetch commands; the step removals already apply on that update.
4. **Disk space.** The system drive has about 5.5 GB free; the worktree's full checkout adds about
   314 MiB there. All clones, mirrors and receivers go to the scratch area on the secondary drive.
5. **Unobserved environments.** macOS, Git below 2.42, real hosts without filter support and machines
   without Windows long-path support stay unobserved; the no-filter case is emulated with a local plain
   server (AC-2).
