## 1. Objective

Ship, as instruction text plus one Git attributes file, a TFW that is installed and updated by
transferring only the framework and a small, named remainder instead of the development repository:

- `update.md` Step 0 fetches the pinned object's framework payload with one written Git-only method
  (≈0.64 MiB instead of ≈114 MiB), shows a silent full download instead of hiding it, and keeps every
  pin and provenance guarantee;
- install (quickstart and the three root READMEs) fetches only `.tfw/` and `editions/` (≈0.73 MiB
  instead of ≈123 MiB with full history);
- release archives ("Download ZIP", tag archives) carry only framework material (≈0.5 MiB instead of
  178.9 MiB);
- the new-task startup card shows the installed version against the newest release, once, without
  ever blocking or updating;
- the update procedure loses three repeats that never found anything, and its staging check becomes
  exact.

Value: new users and every receiver move about a megabyte instead of 114–179 MiB, no agent improvises
the download again, repository growth stops reaching users, and silent version lag becomes visible.

## 5. Acceptance Criteria

### AC-1: The update fetches only the framework payload by one written method

Following the Candidate's `update.md` Step 0 verbatim, an update fetches the pinned object's
framework payload into `.tfw/.upstream/` and nothing that DoD 1 excludes.
- [ ] Step 0 names exact commands: a blobless, depth-1, cone-mode sparse clone of the pinned tag with `core.autocrlf=false` and an empty `core.attributesFile`, into staging under `.tfw/.upstream/`; the copy of `.tfw` to `.tfw/.upstream/.tfw`; the check; the deletion of the clone.
- [ ] A size check (`count-objects -vH`) runs right after the clone and the receipt records the figure; above about 2 MiB the text says the download was full and requires disclosure.
- [ ] One disclosed fallback: if Git rejects an option, the clone repeats without filter and sparse options and the receipt records the measured size.
- [ ] An authorized untagged commit uses the `init` + `fetch --depth 1 <SHA>` + `checkout FETCH_HEAD` sequence, with `-c core.attributesFile=` on the command that writes files.
- [ ] No sparse pattern begins with `/`, and no command contains `$0`–`$9` or `$ARGUMENTS`.
- [ ] Measured transfer under 2 MiB for `v3.7.1`, and every framework-owned file raw-byte-equal (`git hash-object --no-filters` against `git ls-tree`, paths passed as arguments) to the pinned tree.

## 6. Technical Guidance

Non-binding; from RES iterations 1 and 2. The Executor may deviate with an RF justification.

- Clone for a tag (S1): `git clone -c core.autocrlf=false -c core.attributesFile= --filter=blob:none --sparse --depth 1 --branch <tag> <upstream> .tfw/.upstream/.clone`, then `git -C .tfw/.upstream/.clone sparse-checkout set .tfw`; for install use `sparse-checkout set .tfw editions`.
- Size: `git -C .tfw/.upstream/.clone count-objects -vH` (`size-pack`, which slightly overstates by the pack index).
- Byte check: for each path, `git hash-object --no-filters <path>` against `git ls-tree -r <commit> -- .tfw`; pass paths as arguments, not on stdin.
- Untagged (S3): `init`, the clone settings, `remote add`, promisor and filter configuration, `sparse-checkout set .tfw`, `fetch --depth 1 --filter=blob:none origin <SHA>`, `checkout FETCH_HEAD` with `-c core.attributesFile=`; a non-tip SHA needs protocol v2 and fails loudly on v0.
- Windows PowerShell 5.1 drops empty arguments, so use `-c key=` forms; `timeout` there is Windows' wait command.
- Git Bash rewrites an argument that begins with `/`.
- `.gitattributes` allow-list shape: `/* export-ignore`, then `-export-ignore` for the kept paths, with `tools/*` and the `.tfw/` state entries re-ignored.
- `update.md` has 173 words of headroom; the replaced Step 0 sentences are about 50 words.
- The version line's limit comes from the agent's own command tool; released Git has no connect limit.
