## Findings

### C1. H3 fails the causal and measurement challenge

H3 predicts a measurable regression introduced by changed entry cues. Four observations
attack that prediction:

1. The RCFR diff preserved explicit Role Lock, complete canonical read, gates, and stop;
   it shortened the proxy by 13 words and delegated preload order to the canonical Read
   Contract.
2. Both known post-RCFR incidents completed the current skill and full workflow reads.
3. CRATM maps to an uncovered existing-task branch, while RTPSN maps to later
   noncompliance; the mechanisms are not common entry non-load.
4. There is no controlled pre/post denominator, repeated trial, pinned model/effort, or
   effect estimate. “Measurable regression” therefore has not been measured.

**H3 verdict: refuted as stated.** The evidence supports the alternative causal
decomposition and weighs against pure non-loading in the two known incidents. It does not
prove that cue wording can never affect behavior; it shows that this dataset neither
attributes the incidents to the cue change nor estimates such an effect.

### C2. A fifth failure class is evidenced in topology, but not in the incidents

Beyond non-invocation, non-load, uncovered path, and post-load noncompliance, the checkout
exposes **authority/receiver skew**: the manifest and tests authorize plural
`.agents/workflows`, while only singular `.agent/workflows` compatibility copies are
tracked. This can make a command unavailable or stale on a host even when an apparently
similar file exists. It is an evidenced infrastructure risk, not the diagnosed cause of
either CRATM or RTPSN.

### C3. All four entry architectures fail the two-incident substitution test

| Architecture | CRATM uncovered branch | RTPSN post-load noncompliance | Result of attack |
|--------------|-------------------------|-------------------------------|------------------|
| Byte-identical full copy | does not add the missing resume-path rename | the full workflow was already read in the incident | No causal repair demonstrated; adds receiver copies and has a Codex schema blocker. |
| Current thin proxy | leaves canonical branch unchanged | historical baseline includes the deviation | Retainable baseline, not evidence of superior adherence. |
| Strengthened minimal proxy | entry-only wording cannot repair canonical coverage | may increase salience, but the effect is unmeasured; repeating workflow specifics creates a second algorithm | Suitable only as a controlled experiment arm. |
| Direct single authority | removes proxy handoff, not missing logic | supplies the same canonical text that was already loaded | Reduces text/drift in principle; does not address observed mechanisms. |

The strongest counterfactual is RTPSN: replacing the proxy with a full copy or direct read
would still present the same 2,150-word canonical text that the trace shows was read before
the deviation. Any assertion that those architectures would have prevented it requires new
behavioural evidence.

### C4. H4 scorecard: cost/topology can be ranked; adherence cannot

Ratings describe current evidence, not implementation promises.

| Architecture | `/tfw-plan` runtime | Cross-role adherence evidence | Drift surface | Maintenance | Portability | Observability | Evidence-weighted status |
|--------------|---------------------|-------------------------------|---------------|-------------|-------------|---------------|--------------------------|
| Byte-identical full copies | 2,150 words / ~2,867 tokens | none comparative; known incidents already loaded full workflow | high: up to 44 receiver copies for 11 commands | high sync burden, mitigated by hash tests | high for native file-based receivers; blocked as exact current Codex `SKILL.md` | medium: one read is simpler, but lacks a separate entry marker | eliminate as universal near-term choice |
| Current thin proxies | 2,291 / ~3,055 | live baseline; two diagnosed failures, neither caused by proven non-load | medium: proxy contract plus canonical authority | medium; exact source/installed proxy tests exist | high for current Codex; mixed model already accommodates vendor-native copies | high for diagnosing selection vs canonical read | preserve as baseline |
| Strengthened minimal proxies | 2,301 / ~3,068 | no trial; +10-word specimen only | medium, slightly more duplicated boundary language | medium; must prevent proxy from becoming algorithm | same as current Codex route | highest at pre-action boundary if traceable markers are used | retain as experiment arm, not production recommendation |
| Direct single authority | 2,150 / ~2,867 after root context | none comparative; same canonical content | lowest textual drift | low steady-state, high migration cost | low-to-medium: root convention and symlink/schema support are vendor-specific | medium: fewer read boundaries, weaker standalone skill discovery in root-only form | retain as future feasibility arm |

**H4 verdict: inconclusive on its decisive claim.** No architecture has demonstrated
materially better cross-role adherence. The current thin proxy has the best total value as
an evidence-weighted operational baseline because it is live, schema-valid, observable,
and inexpensive relative to the canonical workflow. That is a provisional engineering
recommendation, not proof that it is behaviorally superior.

### C5. Cross-role evidence is asymmetric

| Role | Commands in manifest | Live/behavioural evidence available here | Consequence |
|------|---------------------:|------------------------------------------|-------------|
| Coordinator | 8 | two `/tfw-plan` incident traces, both after full load | diagnoses two mechanisms but not an architecture effect |
| Researcher | 1 | this iteration entered the live repository skill and followed stage gates | one self-observation, not an independent trial |
| Executor | 1 | static Role Lock, source, receiver, and parity evidence only | adherence claim untested |
| Reviewer | 1 | static Role Lock, source, receiver, and parity evidence only | adherence claim untested |

“Cross-role” is therefore not satisfied by the available behavioural sample. Aggregating
the 11 static routes would inflate confidence without adding behavioural observations.

### C6. The least-regret next experiment is bounded and falsifiable

Iteration 1 does not run it, but a later approved research iteration can compare only three
arms: current proxy baseline, the 151-word strengthened proxy, and a schema-valid direct
prototype. Full copies need not be a separate Codex arm if their runtime content is the
same canonical body as direct entry; their distinct maintenance/portability costs can be
tested structurally.

A concrete evaluation contract:

- pin model and reasoning effort; keep canonical workflows and root instructions fixed;
- use new/resume/uncertain-path fixtures for Coordinator plus representative Researcher,
  Executor, and Reviewer fixtures;
- grade R2 invocation, R3 complete load, Read Contract order, forbidden-artifact violations,
  gate/stop compliance, and final routing separately;
- repeat each fixture sufficiently to report proportions and 95% confidence intervals;
- call an arm materially better only if aggregate adherence improves by at least 10
  percentage points, the 95% interval for the difference excludes zero, and no role loses
  more than 5 points;
- report actual input tokens and elapsed time from runtime telemetry instead of the word
  proxy used in this iteration.

OpenAI recommends beginning from the smallest prompt that preserves the product contract,
benchmarking accuracy/token use/latency, defining success and stop rules, and increasing
prompt specificity only when evals show a measurable gain. That guidance attacks both
premature full-copy expansion and unsupported confidence in a ten-word cue change.

Source: [OpenAI — Model guidance for GPT-5.5](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.5).

### C7. Recommendation after Challenge

Preserve **current thin proxy + canonical workflow** as the production baseline for now.
Do not attribute the two incidents to RCFR entry cues and do not expand byte-identical full
copies across adapters. Address known path-coverage defects in their canonical workflows,
add traceable entry/load/conformance evidence to future validation, and treat the
strengthened 151-word proxy and schema-valid direct route as controlled comparison arms.

The immediate consequence is deliberate: no architecture migration is justified in this
iteration. This avoids 44 synchronized algorithm-bearing receiver copies and avoids a
cross-vendor symlink/schema migration, while accepting the measured `/tfw-plan` overhead
of 141 words (~188 estimated tokens) until behavioural evidence can justify change.
