### C4 — Host isolation and subscription claims do not become true through better traces

The [official Git worktree documentation](https://git-scm.com/docs/git-worktree), reread 2026-09-28, describes shared repository data with specific per-worktree metadata. Therefore worktrees solve checkout separation, not a claim of user access isolation. The [Docker Engine security documentation](https://docs.docker.com/engine/security/), rechecked the same day, identifies daemon privileges and host access as material security boundaries. A container name is likewise no substitute for measured mounts/credentials/user permissions. These technical sources cross-check the earlier host observations, not a new host trial.

The later two-project design must retain ordinary-user positive and negative access controls, actual concurrent units and result reconstruction. Bound the threat model: the observed privileged-capable operator is not constrained like an ordinary project user. Do not add a hardening project unless an actual acceptance gap demands one; if the available setup cannot meet the selected access boundary, return that limitation to the owner.

H1 remains partly contradicted and otherwise unresolved: inspected OpenAI conditions reject several people sharing one individual account; current Linux entitlement, organizational contract/seats, comparable workload and costs have not been verified. No repeated token parsing, fabricated billing evidence or public catalogue price closes that gap. Phase B must not run a prohibited shared login or silently substitute a different economic arrangement. A permitted alternative can be proposed through the already reserved owner decision, and only a change to frozen scope needs an amendment.
