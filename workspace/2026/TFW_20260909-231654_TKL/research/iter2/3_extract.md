## Findings

### E1. Concrete handover and replay outcomes

These are explicit semantic walkthroughs, not observed native producer or filesystem-failure runs. The consumer exercise below tests only one read-only use case.

| Case and input | Correct shared outcome | C1 effect | C3 effect |
|---|---|---|---|
| H-MISSING: dispatch identifies Researcher A and Executor B; only A returns a source | Block selected close for B's material return; do not infer absence of knowledge | No row update can replace B's return | A record from A cannot cover B |
| H-NONE: B says it checked its declared task context and prior source S already contains all relevant material; S resolves | Accept B's justified-none handover for that scope; no duplicate publication | Reuse S, no filler row | Reuse S, no filler record |
| H-UNAVAILABLE: B says its earlier session cannot be accessed and the missing decision determines the output | Record unavailable material and route to its existing owner; close remains open until the requirement is honestly resolved | Do not populate a reassuring summary from A | Do not publish an empty accepted record |
| H-RETAIN: a rejected approach yields an uncertain observation irrelevant to current acceptance | Preserve source with an authorized retain-only reason; it is not accepted project truth or a promised future job | Qualifying owner need not append a current rule | Qualifying owner need not promote a new current record |
| R-DUP: source claim key T/A/7 already has accepted publication P; retry requests identical intent/content | Read actual P and acceptance; reuse the completed effect and repair only missing reference | Same row/key and preserved acceptance; no second row | Same record identity; no second file |
| R-DIVERGE: retry uses T/A/7 but changes a material statement | Refuse replacement; preserve both observed values and obtain an authorized correction | Do not overwrite a current topic row under the old retry | Do not overwrite old record or silently invent a second accepted identity |
| R-TWO: distinct sources independently repeat one claim | Inspect independence and applicability; relate evidence or explicit duplicate rather than counting copies as confirmation | One qualified current row may cite both | Equivalence relation or a shared qualified claim retains both sources |
| R-CONFLICT: two independent claims overlap scope and disagree; no ruler decision | Keep unresolved, stop only dependent action, route both to the actual authorized resolver | Topic's current presentation must expose both or unresolved state | Cleanly merged files remain competing claims; latest timestamp is not a ruling |
| R-CONTROL: accepted publication exists, closing reference missing, all material inputs unchanged | Existing PTTC record recovery validates actual effects and repairs only current carrier | No topic re-promotion | No record re-promotion |
| R-LATER: interruption preserved old value X, intended Y, but affected current field is Z | Refuse that affected write and preserve later work | No whole-topic restore | No overwrite of a later successor branch |

The identity distinction is consistent with [AWS's primary retry-design account](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/): a caller's request identity conveys intent and equal parameters alone do not always identify one operation. TKL's actual authority and source roles remain repository-defined. Reopened for this stage on 2026-09-13.

### E2. Function-retention cost: count necessary jobs before files

| Existing function | Refined C1 retains/replaces | Mixed C3 retains/replaces | Cost discriminator |
|---|---|---|---|
| Architecture map | Existing map, updated only for real component changes | Same concise map and stable entry | Both have a justified docs write; no benefit from renaming alone |
| Decision/rationale/source | Current decision rows plus retained historical sources | Keep old D rows; add independent decisions and predecessor relations | C3 needs record form and relation reader; C1 needs serialized shared decision update |
| Important artifacts and legacy replacements | Existing useful links/rows, no every-task inventory | Source links in current decisions/map and preserved legacy links | Both must prove actual source/compiled navigation; SLC C2 resolver is the current accepted input |
| Accepted topic meaning and applicability | Current topics with explicit scoped correction | Preserve legacy topics; new records cite exact legacy identities | C3 avoids converting every historical fact but has a mixed read route |
| Producing-role capture | Reuse role/stage sources, necessary fallback and handover evidence | Same | Equal mandatory job; all-new contributor files are not a C3 prerequisite |
| Qualification/contradiction | Existing authorized Coordinator; completed disposition | Same owner with separate records | Equal semantic work; no autonomous truth promotion |
| Counts/digest reconciliation/processed markers | Retire live bookkeeping and replace protected-action obligation | Same | Both remove the counter problem; C3 cannot claim that benefit exclusively |
| Replay and correction | Stable source/publication identity in row/effect references | Stable record/source identities plus successor/conflict references | C1 serializes overlapping writes; C3 transfers some cost to relation discovery |
| PV/current knowledge access | Update readers to scoped current topic/decision sources | Update readers to entry/record relations plus legacy fallback | C3 has the larger new read-contract burden; both need independent application evidence |
| Migration, clean init, adapters and docs | Remove old gate/state obligations with preserved sources and clean templates | Same plus new record form/mixed readers | Both require source-pinned guide, selected adapter sync and this receiver's actual adoption |

No measured total TKL implementation file/LOC estimate is claimed. Exact affected paths and immutable VALUE denominator belong to the later TS. C3's expected gain is fewer overlapping publication writes; its expected cost is new relation/currentness instructions.
