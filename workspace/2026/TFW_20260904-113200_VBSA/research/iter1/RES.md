## Research Context

Iteration 1 tested whether one semantic value-bearing surface can replace mutable whole-repository budget arithmetic and whether TFW should retain universal hard numerical ceilings after that repair. It reconstructed the current carrier chain, replayed fixed Git ranges across TFW RCFR Phase A, Helpdesk BIAI Phase A, and completed AFD-38 A1.2.2 evidence, compared hard, soft, nonnumeric, and flow controls, and challenged authority boundaries and edge classifications. The research is read-only outside this iteration and treats any change to the frozen HL as an amendment proposal.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Keep exactly four semantic classes: `VALUE`, `ASSURANCE`, `TRACE`, and `DERIVED`. | The three corpora and cross-domain edge matrix need no fifth class when accepted-output and necessary-constituent precedence are explicit. |
| D2 | Classify by approved purpose, with accepted output first and unresolved ambiguity conservatively treated as `VALUE`. | Path, extension, “internal,” “test,” and “generated” labels can all hide real accepted value; conservative defaulting closes the gaming channel without line-level classification. |
| D3 | Measure one immutable baseline-to-candidate diff intersected with the declared `VALUE` surface; any later `VALUE` edit creates a new candidate. | RCFR's `VALUE` result remains 32 paths/2,329 touched LOC while whole-tree totals rise through later trace commits. Mutable Reviewer `HEAD` cannot reproduce execution-time status. |
| D4 | Define logical changed/new/modified file counts and touched text LOC exactly, but mark LOC N/A for binary or non-text value. | Git can reproduce text arithmetic and rename status; it cannot turn heterogeneous deliverables into comparable LOC. N/A is truthful, while zero is not. |
| D5 | Treat the four existing configured numbers as default decomposition/disclosure triggers over applicable `VALUE` measures, not universal vetoes. | BIAI preserves a useful quantitative growth signal, but the owner decision and external evidence show that one cutoff is not a sufficient quality or value verdict across projects. |
| D6 | Permit an explicit task-local hard constraint only when the TS names the protected harm, subject, applicable metric/selector, pre-write enforcement point, and escalation authority. | AFD's exact corrective boundary was useful because it protected a named containment slice; that does not justify a universal hard ceiling. |
| D7 | Bound Coordinator authority to implementation growth necessary for an unchanged frozen Goal, Value, accepted deliverables, AC, DoF, and phase boundary; reserve any outcome expansion to the Owner. | This supports learning without allowing the Executor to widen its grant or the Coordinator to redefine the approved result. It requires an Owner-ruling amendment to current authority language. |
| D8 | Exclude ordinary assurance from delivery-size arithmetic while retaining evidence relevance, proportionality, safety, quality, and review gates. | “Not budget-bearing” is not “optional.” A test, evaluator, or conformance suite becomes `VALUE` when it is itself the accepted product. |
| D9 | Reuse conventions, TS, RF, EV, REVIEW, and existing adapter synchronization; add no manifest, registry, script, or configuration key. | These carriers already form a writer/reader chain. A new artifact would duplicate membership and create another stale state. |
| D10 | Fail closed when refs, selector, class resolution, metric, or method disagree: report `INVALID/BLOCKED`, not under/over. | A numerical verdict without one shared contract is not an enforceable measurement and must not be repaired by reconstructing a new filter at review time. |
| D11 | Recommend `MORE NEEDED` after iteration 1. | The required second iteration must test non-code/binary tasks, adversarial authority cases, and compatibility wording before a TS can safely change universal control semantics. |

## Conclusion

Iteration 1 established that VBSA's four semantic classes, fixed references, and existing carrier chain can remove RCFR's self-referential accounting without hiding BIAI's real product growth, while AFD shows that a narrowly justified hard slice can still protect a concrete harm. The investigation would have missed this distinction if it had only repaired the counted subset: H4's universal-hard premise is not supported, but eliminating numbers entirely is also weaker than the evidence. The strongest design is a configured soft VALUE signal, optional reason-bound task-local hard constraints, and tightly bounded Coordinator authority inside an unchanged frozen outcome, with Owner authority preserved for actual expansion. The main limitation is corpus breadth and untested governance compatibility, so iteration 1 is complete but the research program is not yet sufficient for TS.
