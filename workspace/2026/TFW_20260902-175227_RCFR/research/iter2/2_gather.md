### G2: Candidate-section task digests form a computable Knowledge Gate cursor

Three alternatives fail at least one required replay before implementation:

| Cursor | No-op/threshold | Retry | Equal timestamp | Late candidate | Migration |
|---|---|---|---|---|---|
| numeric sequence | cannot compute for timestamp IDs | simple if sequence exists | n/a | misses edits to an old task | cannot map mixed identifiers safely |
| timestamp watermark | computable from current IDs | state-last helps | ambiguous for equal-second IDs | misses edits behind watermark | legacy IDs require invented ordering |
| processed artifact paths | counts files, not tasks | path marker can retry | safe | detects new artifact, not edited section unless extra hash | path moves and renamed revisions complicate state |
| task → candidate-section digest | exact distinct-task delta | recompute and dedupe | timestamps irrelevant | changed section reopens task | full reconciliation seeds map without inference |

The fourth design is one complete algorithm, rather than a choice left to implementation:

1. Enumerate every resolvable task directory under ordered `tfw.task_containers`, including readable legacy task directories without `status.md`; do not count phase directories as tasks. Reuse the identifier/path resolver used by `.tfw/scripts/gen_index.py`. Duplicate normalized IDs, an ambiguous path, or disappearance of a previously recorded task is a hard stop because state could otherwise conceal a trace.
2. For each task, select sections by heading name rather than section number: `Fact Candidates`, `Strategic Insights`, `Strategic Session Insights`, and `Execution Session Insights` in HL, RF, REVIEW, RES and their revisions/iterations/phases. Include explicit `No ...`/empty candidate sections. Normalize line endings to LF, preserve the section body bytes otherwise, sort tuples by repository-relative path then heading occurrence, and hash `path NUL heading NUL body` tuples with SHA-256. Hash an explicit empty tuple for a task with no selected section.
3. Store the result as `knowledge.processed_task_digests: {full_task_id: sha256}` in `.tfw/knowledge_state.yaml`. `last_consolidation_date` remains audit metadata. Remove `last_consolidation_seq`; no workflow may derive order from it.
4. The read-only check computes the current map. A missing ID or changed digest is one pending task. `delta` is the number of distinct pending task IDs, including tasks whose selected sections currently contain no candidates. This preserves the configured task-interval meaning and makes a later candidate edit reopen the task.
5. In `plan.md` Step 2: `off` skips; `soft` reports `delta/interval` and continues; `hard` stops and routes to `/tfw-knowledge` when `delta >= interval`, otherwise continues. With zero pending tasks, the result is an explicit no-op.
6. `/tfw-knowledge` reads candidate sections only from pending tasks, then applies the existing Human-Only Test, deduplication, contradiction, verification and two WAIT gates. It recomputes topic counts from files; statistics are derived totals, never blind increments.
7. Commit order is semantic: write approved topic/KNOWLEDGE changes first, then write the state map last. If interrupted before state, retry sees the same tasks and deduplicates them against current topic facts. Updating state before facts is prohibited. The final approved write should be one commit, but retry correctness does not depend on filesystem transactionality.
8. Migration when the digest map is absent is a mandatory one-time full reconciliation over every resolved current and legacy task directory. Existing topic facts are the deduplication baseline; contradictions and one-source candidates retain existing human decisions. Only after the full pass succeeds is the complete digest map written and `last_consolidation_seq` removed. Neither the old sequence nor date is used to skip a source.

The current repository gives the migration a bounded observable surface: the task validator reports 61 task roots, 23 have `status.md`, and 49 files currently contain at least one candidate/insight heading. The two currently reported task-validation problems are independent inputs that the migration must report, not silently repair. A 61-entry digest map is roughly linear state growth and is read by the checker, not injected into every role prompt.

### G3: Clean baseline/candidate fixtures must compare behavior, not prose

A useful fixture is a minimal temporary receiver containing only the files named by the command's read contract. Baseline means current canonical sources and full mandatory foundation. Candidate means the addressed read manifest and proposed compact glossary/history content. The same scenario is executed twice. Equivalence requires the same decision or refusal, same allowed/forbidden artifact set, same mandatory citation target, and same gate outcome; wording and token count may differ.

| Fixture | Minimal stimulus | Required baseline/candidate outcome |
|---|---|---|
| P1 ID collision | requested ABBR produces an existing full timestamp ID | refuse creation; no task artifact; cite identifier rule |
| P2 frozen change | research recommends altering approved HL §3/§5 claim | amendment proposal + WAIT; no silent HL edit |
| P3 free refinement | evidence extends HL §9 risk only | Coordinator may update §9; frozen sections unchanged |

| E1 blocking ONB | unanswered blocking question | WAIT; no implementation edit |
| E2 dependency | prerequisite AC fails | dependent AC not executed; record failure |
| E3 build/evidence | build fails or artifact is absent | no RF success/VERIFIED claim; failure is explicit |
| E4 revision return | highest TS revision and prior REVIEW exist | use highest TS, prior REVIEW rationale, append new ONB/RF lineage |
| V1 discrepancy | sampled RF claim disagrees with file | verification escalates to 100% |
| V2 purpose failure | ACs green but frozen purpose is unmet | REJECT or return to owner; never APPROVE |
| V3 REVISE condition | proposed round lacks cited AC/frozen claim | do not allocate round; dispose or reject item |
| V4 rung 2 | review finds frozen-claim conflict | proposal to Coordinator; Reviewer does not edit TS/HL |
| C1 docs scope | approved minor task | REVIEW marker `tfw-docs: N/A`; no topic/§4 write |
| C2 knowledge retry | facts written, state write interrupted | next run deduplicates; no duplicate fact/stat increment; state converges |
| C3 resume discovery | stale derived index disagrees with task status | status wins; no action from stale index |
| A1 adapter command | each supported adapter receives literal `/tfw-*` | exact canonical workflow/role resolves or fixture fails before semantic comparison |

Every fixture output record must contain `{decision, refusal_reason?, artifacts_created, artifacts_modified, citations, gate, read_manifest}`. A candidate passes only on semantic fields; `read_manifest` is compared for the expected reduction and absence of unknown full-library reads. This catches a seemingly successful answer that reached the right prose while reading an unsupported source.

The official OpenAI model-transition guidance recommends removing one instruction group at a time and rerunning representative evaluations, and reports directional token reductions only as workload-specific evidence, not a universal promise ([OpenAI, “Using GPT-5.4,” migration principles](https://developers.openai.com/api/docs/guides/latest-model)). This supports paired, representative fixtures and forbids treating the word-count result alone as semantic proof.

## Deep-mode Decisions and Metacognitive Check

1. **Measurement decision:** count exact current heading ranges and retain full PV costs; do not estimate future compact prose. This prevents a compression forecast from masquerading as measured proof.
2. **Cursor decision:** treat task identity plus selected-section digest as the only design that can be replayed across all required cases; keep alternatives in the configuration space for Challenge attacks.
3. **Evidence decision:** use deterministic paired fixtures as the required semantic gate and comparative model eval only as optional supplementary evidence. This separates behavior contracts from model phrasing variance.

Metacognitive check: the strongest result, 74.2%, depends on the accuracy of the candidate read graph, while semantic equivalence depends on fixtures that are specified but not yet implemented. The adapter findings are partly direct repository evidence and partly official discovery contracts; no claim is made that an unavailable Cursor binary was live-tested. The digest algorithm deliberately counts no-candidate tasks, which may trigger consolidation with nothing to write, but that is necessary to preserve the configured task-interval semantics and to detect later candidate edits.
