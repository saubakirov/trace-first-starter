### E3: Cursor replay specification

The checker operates on canonical tuples, so its semantics can be tested without real timestamps or network access:

| Replay | Prior map | Current tasks/sections | Pending | Gate/result |
|---|---|---|---|---|
| K0 no-op | hashes A–E | identical A–E | 0 | continue in hard/soft; off skips |
| K1 below threshold 5 | hashes A–E | A–E + F–I | 4 | hard continues; soft reports 4/5 |
| K2 threshold | hashes A–E | A–E + F–J | 5 | hard STOP `/tfw-knowledge` |
| K3 retry | hashes A–E | F fact already written but old state; source marker changes F digest | F | dedup fact, recompute totals, then store F digest once |
| K4 migration | no map, legacy seq/date exist | 61 current/legacy task roots | all 61 reconciliation inputs | no source skipped; write full map only after approval |
| K5 equal time | A and B IDs share timestamp, different ABBR | both absent from prior map | A,B | pending=2, deterministic lexical output |
| K6 candidate | A old hash | A Fact Candidates body changed | A | pending=1 and candidate gathered |
| K7 no-candidate | no A | A has no selected heading | A | pending=1, gathers zero, records empty digest after run |
| K8 late candidate | A empty digest stored | A gains a Fact Candidates section | A | changed digest reopens A |

An additional negative case is mandatory: a prior-map task disappears or two paths normalize to the same ID. The checker returns a trace problem and no gate arithmetic. This prevents a deletion from being interpreted as successful processing.

The use of a content digest is an integrity/change detector, not a proof that the candidate is true. Git's official documentation describes object IDs as computed from content and content addressing as independently checkable; this supports using a digest to detect changed selected sections ([Git `hash-object`](https://git-scm.com/docs/git-hash-object), [Git hash-function transition](https://git-scm.com/docs/hash-function-transition.html)). Existing TFW human verification still decides truth. The retry rule is deliberately idempotent: official AWS guidance defines idempotency as repeated calls having the same state effect as one and recommends it for retryable operations ([AWS Prescriptive Guidance, retry/idempotency](https://docs.aws.amazon.com/pdfs/prescriptive-guidance/latest/cloud-design-patterns/cloud-design-patterns.pdf)).

### E4: Adapter receiver fixture topology

The clean-receiver test begins from a temporary directory containing `.tfw` canonical sources and the adapter source package, not this repository's already-populated installed directories. For each adapter it runs the same install mapping as `init.md`, then asserts:

1. persistent rule file exists at the vendor's documented path;
2. the exact set `{plan,research,handoff,review,resume,docs,knowledge,release,update,config,init}` is present once;
3. `/tfw-research` resolves `Researcher`; plan/knowledge/config/docs/release/update/init/resume resolve Coordinator; handoff resolves Executor; review resolves Reviewer;
4. each command points/copies to the canonical workflow expected by the mapping;
5. the persistent rule and command together produce the expected E1 read set with no unknown full-library edge;
6. installing twice is a no-op; update repairs one altered managed copy and leaves unrelated receiver content intact.

Live installed-tool invocation is supplementary, not required for deterministic packaging proof. On this host Codex, Claude and Antigravity executables exist; Cursor does not. Making pass/fail depend on an installed UI would make receiving-project compatibility non-portable. Vendor discovery documentation supplies the path contract, and filesystem/semantic fixtures test the framework's side of it.

## Deep-mode Decisions and Metacognitive Check

1. **Architecture decision:** carry C9 into Challenge as the reference candidate and C10 as a later compaction refinement. C9 already clears the numerical requirement without creating a generated runtime authority.
2. **State decision:** reuse `gen_index.py` for read-only digest computation rather than adding a new runtime script or persistent cursor artifact. The knowledge state remains the only cursor authority.
3. **Proof decision:** make semantic fixtures and adapter command-role parity phase gates; word-count reports alone cannot approve a phase.

Metacognitive check: the catalogue is intentionally broader than a single TS phase and must be classified by the Coordinator against frozen Phase A/B/C boundaries. Recommended wording preserves current algorithms as observed, but only Challenge can expose interactions such as a processed marker changing its own digest, a missing historical source, or a vendor path whose official documentation differs from existing repository assumptions. The digest design stores one hash per task and therefore adds state; its named reader/job and the removal of sequence scans satisfy the addition test, but growth and trace-loss behavior still need stress testing.
