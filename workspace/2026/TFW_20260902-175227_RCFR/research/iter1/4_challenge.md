**Unexpected survivor:** C2. A physical file split is not required for progressive disclosure. A compact monolith remains viable if stable headings are the address contract and validation proves that roles load only the named ranges. C2 loses to C8 operationally because a large mixed file is easier to regress into full-read behavior, not because it is semantically invalid.

## Findings

### C1: The numerical result survives conservative attacks

The Extract model deliberately leaves all role workflows, templates, and the full 16,033-word PV scan unchanged. It also grants each primary role up to 3,200 words of addressed shared rules. Under those unfavorable assumptions, reductions remain 55.7% Coordinator, 80.0% Researcher, 89.7% Executor, 69.2% Reviewer, and 74.3% for the fixed minimum-two-iteration trajectory. The smallest margin over the required 30% is 25.7 percentage points.

Three common ways to manufacture a saving were excluded:

1. Task artifacts are variable and remain on both sides; their words are not claimed as savings.
2. PV remains a full independent scan for Coordinator and Reviewer; no project decision or value is hidden by relevance selection.
3. No saving depends on minification, caching, a generated runtime view, or moving a file outside `.tfw`.

The exposed weakness is not arithmetic but proof of the 3,200-word allowance. Current convention sections mix rules and rationale, so iteration 1 can show ample headroom but cannot yet identify every exact operative line that each role must retain. A line-level extraction in iteration 2 must replace the allowance with measured ranges.

### C3: Deliberate inline repetition that should survive

Not every repeated sentence is accidental. These repetitions have a distinct enforcement use and should remain compactly inline:

| Repetition | Why a pointer alone can fail | Boundary |
|-----------|------------------------------|----------|
| workflow role lock and forbidden output | it must prevent the current role from acting before any optional library lookup | workflow states the local act/refusal; conventions states only cross-role routing grammar |
| WAIT/STOP at the exact checkpoint | a terminal gate is an execution instruction, not background knowledge | each workflow keeps the local stop; skill merely names the workflow |
| enforcement-critical config default beside the check | a missing external config must still yield deterministic behavior | one compact default at the enforcement site; registry verifies it against `project_config.yaml` |
| field-local status vocabulary in EV/REVIEW templates | the writer needs the allowed value while filling the field | template lists values; workflow owns when the field is evaluated |
| independent PV scan for Coordinator and Reviewer | independent judgment is a separate decision use, not duplicate authority | both read the same authoritative sources; neither copies their content |
| stage mindset and completion marker | it shapes the local OODA act and makes omission visible | stage template owns the cue; base workflow owns stage order |

Incident rates, origin stories, full template skeletons copied into workflows, and repeated prerequisite lists do not meet this test: they have no separate local decision or refusal that a reference would miss.

### C4: Stale-mechanic repair must precede compression claims

The Knowledge Gate cannot be declared preserved while `current_seq` and `last_consolidation_seq` have no value in clock-derived identifiers. Likewise, `resume.md` cannot prove current discovery while scanning retired `HL__Phase*` names, and the Config Sync Registry cannot prove Pattern-A propagation where named inline locations are absent. These are semantic defects in current paths, not removable explanation.

The Extract recommendations correctly name the affected files, but R10 is intentionally provisional. Counting candidate-bearing unprocessed tasks and storing a timestamp is plausible; it has not yet been checked against no-candidate tasks, repeated consolidation, migrated state, and equal-timestamp events. Iteration 2 must select and replay the cursor before TS. This is the largest open algorithmic question.

### C5: Clean-context equivalence is evidence, not a writing preference

OpenAI's Evals API models an evaluation as explicit input context plus testing criteria and supports running the same structured evaluation across model settings ([OpenAI Evals API](https://platform.openai.com/docs/api-reference/evals)). Applied here, the robust proof is a fixture matrix with fixed task inputs and expected decisions—not a reviewer reading both old and new prose and judging that they “look equivalent.”

The minimum suite must cover Coordinator freeze/amend and Knowledge Gate choices; Researcher stage order, external-source requirement, iteration ceiling and hard stop; Executor onboarding, first pass, revision and evidence/RF gates; Reviewer independent map/verify/judge, citation bar, purpose failure and disposition; plus resume and knowledge-close paths. Each case records required inputs, expected reads, expected decision, forbidden decision, and citations. Run baseline and candidate from fresh context; compare decisions and artifacts, not prose resemblance.

Iteration 1 defines that proof contract but cannot execute it because no implementation candidate exists and the user explicitly scoped out code/workflow changes.
