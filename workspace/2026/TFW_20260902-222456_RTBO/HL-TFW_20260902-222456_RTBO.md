## 1. Vision 🔒 FROZEN

TFW no longer maintains a committed portfolio cache or lets a harmless wording choice in one old
journal event become every later agent's problem. Task state remains quick to inspect at project
scale, but discovery and diagnostics are read-only aids: they never become authority, a routine
workflow duty, or a runtime prerequisite for using the method.

**Impact:** A task changes only its own state and trace. A person or agent can still obtain a current
portfolio when it is useful, while ordinary Full TFW work remains possible without Python; Assisted
remains prompt-first and receives no lifecycle or diagnostic runtime.

> “Keep the list available when it helps, but stop making everyone maintain it and stop turning an
> accidental 123-character sentence into a permanent red warning.”

## 4. Phases 🔒 FROZEN

  preserving cited trace reachability.

  changelog, adapters, and assurance together; historical records remain historical.

## 5. Definition of Done (DoD) 🔒 FROZEN

- ✅ 1. A normal task transition changes only that task or phase; no workflow, test, README route, or
  release rule requires regenerating or committing a portfolio file.
- ✅ 2. The repository contains no authoritative or required committed `00-INDEX.md`; absence and
  staleness cannot fail a task, build, review, initialization, update, or release.
- ✅ 3. A current portfolio can be obtained read-only from configured task containers and exposes all
  resolved current identities/statuses plus malformed, duplicate, stateless, and unresolved inputs.
- ✅ 4. Full TFW's core lifecycle can be read and advanced without Python, PyYAML, or any helper;
  helper absence is reported only when someone explicitly requests helper output.
- ✅ 5. Any helper retained in Full is explicitly optional, read-only by default, dependency-honest,
  and materially cheaper or safer than ad-hoc agent enumeration at large corpus sizes.
- ✅ 6. Assisted contains no lifecycle/diagnostic script, command reference, dependency, or copied
  implementation originating from this work.
- ✅ 7. Journal guidance asks for a brief one-line summary, normally no more than 120 code points, but
  no parser or checker rejects length; the existing 123-character event passes without being edited,
  deleted, or specially exempted.
- ✅ 8. Material status, transition, identity, reference, and project-consistency defects remain
  observable; advisory prose length cannot produce a non-zero health verdict.
- ✅ 9. CI may derive a current portfolio page without committing it. The published navigation keeps
  the task traces required by real citations reachable but does not make the entire task corpus a
  primary competing documentation product.
- ✅ 10. The accepted boundary between optional Full utility and maintainer-only doctor is stated once,
  tested from a clean receiving project, and not inferred from where this upstream repository stores
  its own tools.
- ✅ 11. Existing migration history and board snapshots remain readable; users upgrading an older Full
  installation receive an explicit path that does not turn a one-time migration helper into permanent
  runtime machinery.
- ✅ 12. Current canonical sources, generated adapter copies, documentation compilation, and relevant
  tests agree on the same non-gating model, with no obsolete `build gate` wording.

## 6. Definition of Failure (DoF) 🔒 FROZEN

- ❌ 1. `00-INDEX.md` is replaced with another committed cache, generated registry, or shared file that
  routine task work must refresh.
- ❌ 2. The known 123-character event is edited, deleted, normalized, or exempted by path instead of
  removing the invalid universal length rule.
- ❌ 3. “Normally ≤120” remains a machine-enforced limit, exit-code condition, or review finding with no
  material consequence.
- ❌ 4. Removing index maintenance also removes exact identifier parsing, hides malformed inputs, or
  makes a selected task's state depend on an aggregate view.
- ❌ 5. Python or PyYAML becomes a silent prerequisite for planning, knowledge consolidation,
  initialization, update, ordinary execution, or review.
- ❌ 6. Full's optional tooling or this repository's maintainer tooling appears in Assisted.
- ❌ 7. The public site loses cited task traces or breaks artifact links merely to declutter its primary
  navigation.
- ❌ 8. A broad `tfw-doctor` feature is improvised inside this task without a separate evidence-backed
  scope for the historical TFW-16 ambitions.
- ❌ 9. Real structural corruption is downgraded to advice merely because the old report was noisy.
- ❌ 10. Historical changelog, migration, proposal, RF, REVIEW, or knowledge evidence is rewritten to
  pretend the earlier design never existed.

**On failure:** Stop the phase, preserve the last verified state, and return to `/tfw-plan` with the
failed criterion and the smallest architecture-level alternative. Do not patch a noisy symptom.

## 7. Principles 🔒 FROZEN

1. **Local truth, disposable projections** — task and phase `status.md` files own state; listings,
   documentation pages, and health reports are downstream views with no write-back authority.
2. **Guidance is not a gate** — concise prose can be prompted and reviewed by judgment; a numeric rule
   earns enforcement only when its violation causes material harm and a writer can comply before acting.
3. **Optional code must be honestly optional** — shipping a convenience does not authorize a hidden
   runtime prerequisite, and the absence of that convenience does not stop the method.
4. **One parser when exactness matters** — large-corpus discovery must not invite every agent to invent
   incompatible identifier, state, and unresolved-input rules; retain shared deterministic logic only
   where research demonstrates its value.
5. **Edition boundaries are product boundaries** — Full may justify optional deterministic tooling;
   Assisted remains prompt-first and runtime-free.
6. **Build products stay at build time** — a page produced for CI documentation is not a source artifact
   or maintenance duty in Git.
7. **Trace reachability over trace prominence** — cited historical reasoning must remain reachable,
   while the main documentation navigation serves understanding and use of TFW rather than showcasing
   the volume of its own process.
8. **Architecture over suppression** — remove the cause that produces the 123 warning and shared-index
   churn; do not hide one message, special-case one event, or silence every diagnostic.
9. **No speculative doctor** — reuse proven checks where useful, but treat TFW-16's broader
   self-diagnosis concept as separate unapproved product scope.

## 10. RESEARCH Case 🟢 FREE

### Blind Spots

- Whether a canonical optional collector materially outperforms an agent's native filesystem scan at
  100, 1,000, and malformed-task corpus sizes.
- Whether Full can ship the collector without users or agents treating Python/PyYAML as mandatory.
- Which public documentation surface is actually valuable: a current list, primary clickable task
  navigation, citation-only trace reachability, or none of them.
- Which current checks protect material state/continuity and which are merely authoring preferences.
- How to preserve the selected-section Knowledge Gate and one-time migration without keeping the whole
  current monolith as required runtime.

### Hypotheses

| # | Hypothesis | Status |
|---|---|---|
| H1 | At hundreds or thousands of tasks, one canonical read-only collector prevents material omissions and identity mistakes that ad-hoc agent enumeration cannot prevent cheaply | refuted — owner: a capable agent will write a fit-for-environment script rather than enumerate files manually; scale alone does not justify shipped runtime |
| H2 | Full can include an optional status collector without making Python or PyYAML a practical prerequisite, provided every workflow has a complete no-helper path and helper absence never changes lifecycle | needs-research — owner expects installation to be manageable but does not know whether shipping it makes the dependency practically mandatory |
| H3 | A CI-generated current task list helps orientation, while placing the entire task corpus in primary site navigation distracts from TFW's philosophy and use; citation-reachable traces are sufficient | needs-research — owner sees possible value in the generated list but doubts the practical value of broad clickable task navigation |
| H4 | Material task/project integrity checks can be separated from advisory authoring guidance so that the known 123 event becomes quiet without reducing detection of malformed state, illegal transitions, duplicates, or missing authority | needs-research — desired policy is confirmed; the safe diagnostic classification and regression proof remain open |

### Risks of Not Researching

Without research, moving the script out of Full may silently break the Knowledge Gate, migration, and
documentation resolver; keeping it may preserve an undeclared runtime dependency and invite agents to
treat optional reports as gates. Removing task navigation on taste alone may also sever the trace graph
that earlier documentation work explicitly protected.

### Proposed RESEARCH Focus

1. **Gather:** Map every function and consumer of `gen_index.py`, including clean Full receivers,
   documentation CI, Knowledge Gate, migration, and Assisted exclusion; exercise no-Python and
   no-PyYAML conditions without changing project state.
2. **Extract:** Compare three ownership shapes — optional Full utility, maintainer-only doctor, and a
   split shared core — against corpus scale, portability, duplication, failure behavior, and user burden.
3. **Challenge:** Test the public documentation alternatives separately: generated status list,
   primary task navigation, citation-only trace pages, and no task surface; verify actual link and
   continuation consequences rather than visual appeal.
4. **Challenge:** Classify every current diagnostic by material harm, compliance timing, and authority;
   prove the soft-summary model on the existing 123 event and synthetic structural defects.

### Why Not Just...?

- Why not delete `gen_index.py` with `00-INDEX.md`? — The module also owns exact identifiers,
  Knowledge Gate digests, project checks, migration support, and documentation parsing.
- Why not keep everything and stop running it? — Mandatory invocations, stale “build gate” language,
  the undeclared PyYAML dependency, and three post-proposal refresh commits show that prose alone does
  not make the machinery optional.
- Why not special-case the 123-character event? — It would preserve the invalid universal rule, edit
  the meaning of immutable history, and guarantee the same distraction at the next overrun.
- Why not add the broad `tfw-doctor` now? — TFW-16 includes behavior and knowledge-gap analysis beyond
  the measured portfolio/status problem; naming that product does not supply its contract.
