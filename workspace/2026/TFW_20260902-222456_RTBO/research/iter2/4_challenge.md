# Challenge — "What do we NOT expect?"
> **Mindset:** Critic. The candidate architecture is now attacked against concrete counterexamples.
> **Test:** "Would the surviving configuration still work if the helper, runtime, navigation entry, or prose ceiling disappeared?"
> Parent: [HL-TFW_20260902-222456_RTBO](../../HL-TFW_20260902-222456_RTBO.md)
> Goal: TFW keeps task state inspectable at scale without a committed portfolio cache, a hard prose-length gate, or a runtime prerequisite.

## Consistency Check

**Incompatible pairs:**

| Dimension A | Alternative | Dimension B | Alternative | Why incompatible |

| Migration delivery | guide plus default agent synthesis | exact compatibility accounting | write receiver state | There is no proof that a newly synthesized migrator preserves manifests, history, rollback, and idempotency before the first destructive write. |

| Prose policy | remove every numeric limit indiscriminately | source-derived experiment/corpus capacity | scoped operational constraint | The latter limits protect a different object and were not shown to be prose-validity gates. |

**Unexpected survivors:**

- **Runtime asymmetry survives:** Full can require no executable in ordinary operation while a one-time
  crossed-major migration honestly requires a temporary compatible environment. The dependency is
  attached to the compatibility product, not silently inherited by the installed method.
- **Hidden task landing survives without a library:** a landing is a link-integrity target, not a
  navigation promise. It can be generated and directly linked without publishing a browsable task
  portfolio.
- **No-helper exactness survives, regex does not:** the independent .NET digest matched the production
  oracle, but only after the configuration was interpreted semantically. The freedom is implementation
  choice, not permission to approximate the carrier.

## Findings

### C1: the no-helper gate survives absence, mutation, and malformed inputs

The strongest attack is not whether another language can calculate SHA-256; it is whether the result
remains exact without silently accepting a partial scan. The practical run answered the positive half:

- independent PowerShell/.NET results matched the Python oracle for the empty tuple, fenced headings,
  a changed selected body, and the real RTBO digest
  `d29d4cab84f8b43a3de0fa838f6525b4b2c5c07272587eecc1dca06f9f072ef5`;
- the helper's 13 focused K0–K9/path/collision tests passed;
- identical state produced no pending task, a removed identity was detected, and malformed/colliding
  identities remained hard problems rather than threshold inputs.

The negative half eliminated a regex fallback. It misread a quoted version, found a commented key,
and treated a comment token as a missing build path. YAML 1.2 permits structures that a line matcher
cannot safely reconstruct; the Full procedure must therefore say **semantic YAML read** or
**available conforming parser**, never prescribe regex extraction. The gate must build the complete
current map, stop on scan/config/identity problems, compare migration/pending/threshold policy, then
recompute after marker work and write digest state last. An unavailable optional implementation is
indeterminate, not proof that the project is clean and not permission to install a runtime.

The residual cost is instruction length and conformance maintenance. It is smaller than shipping the
monolith when the authority is one addressed canonical range and the executable vectors remain
upstream. Duplicating the algorithm into plan and knowledge would fail this challenge.

### C2: migration must hard-stop when its declared environment is absent

`python -S .tfw/scripts/migrate_board.py --help` failed before help because the active import chain
requires PyYAML, while the complete migration suite passed in the prepared maintainer environment.
That disproves both “runtime-free today” and “unreliable logic.” The defect is delivery/placement.

Default agent synthesis is eliminated: a migration can rewrite historical identity and files before
later parity is known. Multi-platform binaries are also eliminated for this task: they add a build,
signing, provenance, OS/architecture, and update matrix without evidence of repeat receiver demand.
The survivor is a pinned, version-addressed upstream bundle under the crossed-major route, with:

1. declared Python/PyYAML requirements isolated from ordinary Full;
2. a source/destination version check and dry-run manifest before writes;
3. no receiver write if the runtime, dependency, source identity, or accounting input is unavailable;
4. the existing history/snapshot/idempotency tests and an identifiable source revision;
5. removal of transient executable material after success while the guide and receiver evidence stay.

A no-Python receiver must use a temporary compatible environment or stop with concrete instructions.
An alternative implementation is acceptable only after it passes the shared vectors and produces the
same dry-run accounting; it is not the default. PyPA explicitly treats dependency groups as internal
development/script requirements that are not part of built project metadata, which supports keeping
this dependency in an upstream tool environment rather than the Full interface:
[PyPA Dependency Groups](https://packaging.python.org/en/latest/specifications/dependency-groups/).
Release provenance or an attestation can establish where a bundle came from, but not justify shipping
it permanently; provenance tracks how an artifact was produced, not whether it has receiver value:
[SLSA Provenance](https://slsa.dev/spec/v1.2/provenance).

### C3: diagnostic epochs separate real corruption from the actual 123-character event

The repository counterexamples force the contract:

| Fixture | Applicable epoch | Material result | Length advice removed | Expected exit |
|---|---|---|---|---|
| actual immutable event with 123-character summary | current historical shape | no structural defect | one former `>120` report disappears | 0 |
| two-part legacy actor-only event | legacy compatibility | accepted as historical shape | no effect | 0 |
| current event missing `on_behalf_of`, empty refs, half transition | current shape | missing actor context, missing/empty refs, incomplete transition | all defects survive | 1 |
| new-write event with `+15:00`, `../escape`, illegal `TODO -> DONE` | pre-install current contract | invalid offset, escaping ref, illegal transition | all defects survive | 1 |
| unreadable input or incomplete scan | any requested diagnostic | result cannot be established | not advice | 2 |
| status with only long title/goal/value/outcome | current status | no structural defect | four former length reports disappear | 0 |
| same status without authority, wrong ID, nonterminal outcome | current status | structural defects survive | length reports disappear only | 1 |

Exit 0 is scoped to the requested diagnostic; exit 1 means at least one material finding; exit 2 means
the diagnostic could not establish its result. Stateless historical phase directories and legacy
shapes can be compatibility notes. Concision advice is exit-neutral in every epoch. A stricter rule
applies to a new write before installation and does not rewrite immutable history merely because the
doctor was upgraded.

This stays deliberately narrower than a universal “health” program. Selected-task pre-write checks
belong in Full prompts. A bounded doctor and corpus-wide structural checks belong upstream and may run
in upstream CI. Ordinary receiving Full gets no automatic whole-corpus report.

### C4: hidden navigation works, but hidden landings are mandatory for bare IDs

The clean-HEAD hidden-navigation build rendered 1,284 task pages and retained both a representative
cited RF target and the knowledge page linking it. Removing `nav["Tasks"]` therefore does not remove
the underlying trace pages. The same build also retained a bare no-HL task link whose folder lacked
`index.html`; navigation hiding does not repair resolver output.

The proposed landing is the smallest coherent repair. CI/docs generation should emit a hidden landing
for every task directory (including no-HL tasks), keep individual trace pages compiled, and test both a
bare ID and a phase-specific citation. The global Tasks navigation entry is deleted. A public or
default current-status page stays absent because no reader/value evidence was found. An explicitly
requested current-status CI artifact is useful for a maintainer snapshot but is disposable, not a
citation surface: GitHub documents default artifact retention and deletion together with a workflow
run [Removing workflow artifacts](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/remove-workflow-artifacts).

This prevents CI from smuggling the rejected portfolio back in: CI **generates link targets** and may
produce an opt-in diagnostic snapshot; it does not commit state, create a public task library, or add a
default portfolio publication duty.

### C5: deleting prose ceilings does not delete structural contracts

The controlled status fixtures show that length checks are separable: filtering only length findings
made a long-but-structural status clean, while missing authority, wrong identity, and an impossible
terminal relationship remained errors. The attack therefore rejects the claim that a global prose
ceiling is needed to preserve machine validity.

Concrete deletion set:

- remove numeric validity for event `summary` and status `title`, `goal`, `value`, and `outcome`;
- remove truncation and the `<=80` ceiling for `lifecycle_verbatim`, because it is exact migration
  evidence rather than prose presentation;
- delete unused `max_summary_length`, `max_index_lines`, and `max_index_facts_lines` configuration;
- remove those findings from checkers, reviews, and CI exit criteria.

Concrete retention set:

- retain presence, scalar/carrier shape, whole identity, declared lifecycle, authority, terminal/outcome
  relation, current ref/time/transition rules, and exact migration evidence;
- retain “brief one-line, normally <=120” and concise-status wording as author guidance only;
- wrap or truncate only generated projections, never stored source evidence;
- leave source-derived experiment and fact/topic capacity limits with their own owners because this
  iteration did not establish that they are prose-validity gates.

The maintenance risk after deletion is verbose pages, not invalid state. That risk is observable at the
projection and is cheaper to solve there than by rejecting durable source.

### C6: final placement, value, cost, and residual unknowns

| Surface | Concrete action | Value preserved / gained | Cost accepted | Residual unknown |
|---|---|---|---|---|
| `.tfw/scripts/gen_index.py` and its Full invocations | delete from Full; move reference collector/doctor behavior and tests upstream | exact gate result without receiver runtime; maintainer diagnostics remain | canonical method text + upstream conformance upkeep | agent semantic reads can vary; mitigated by vectors and hard stops |
| Knowledge Gate contract | retain one addressed Full range; invoke outcome from plan/knowledge | pending/removed/migration policy remains available everywhere | longer explicit workflow contract | no evidence yet from a second agent implementation |
| project checks | retain owning init/update postconditions; move broad report upstream | installation correctness without circular helper-presence rule | some inline duplication of local postconditions | breadth of a future doctor beyond proven checks |
| `migrate_board.py` | remove from active Full; deliver as pinned versioned upstream migration bundle | exact, tested crossed-major route | temporary runtime and explicit stop on bare receivers | frequency of truly no-Python migrations; no case for binary matrix yet |
| diagnostic rules | retain structural/new-write rules; move corpus doctor upstream; add epochs and 0/1/2 | harmless history stays readable; real corruption still blocks | maintain shape applicability table | future schema changes must declare their epoch |
| docs | delete top-level Tasks navigation; generate hidden task landings/pages in CI | citations and bare IDs resolve without public library | more generated pages/build time | readership for any public status view remains unmeasured |
| current-status portfolio | do not commit or publish by default; permit explicit CI artifact | reversible maintainer snapshot | artifact job/storage only when requested | actual consumer/value signal |
| prose constraints | delete disproved numeric validity/dead keys; retain guidance/structure | expressive durable evidence; same machine invariants | projection wrapping and editorial judgment | no measured upper display threshold |
| Assisted | keep unchanged; prohibit RTBO lifecycle/tool imports | preserves prompt-first edition | negative regression check only | none discovered in this iteration |

The survivor fits the frozen boundary: no committed cache, no mandatory ordinary-Full runtime, no
retroactive prose rejection, and no Full/Assisted coupling. The remaining unknowns are adoption/value
questions, not missing feasibility evidence. They justify conservative defaults (no public status page,
no binary migration matrix), not another research iteration.
