## 1. Objective

Remove the tracked task-portfolio cache and every ordinary Full dependency on its Python implementation.
Keep task state directly inspectable, preserve an exact tool-independent Knowledge Gate, and retain only
upstream maintainer tooling: a read-only state library, a bounded project doctor/status collector, and a
versioned pre-2.0 migration bundle. Numeric prose ceilings become authoring guidance rather than validity;
the immutable 123-code-point event becomes clean without being edited; task traces remain directly
linkable in generated documentation without a public Tasks library; Assisted remains unchanged.

## 2. Scope

### In Scope

- Delete tracked `workspace/00-INDEX.md`, index generation/freshness behavior, all current routes to the
  cache, and the obligation to rebuild or commit any portfolio view.
- Remove `.tfw/scripts/` from the Full payload. Move retained semantic reading, conformance, bounded
  project-health diagnostics, status collection, and migration behavior to root `tools/`, which is
  upstream-only and is not copied by `/tfw-init` or `/tfw-update`.
- Provide `tools/tfw_doctor.py` as a deterministic, read-only maintainer CLI with `status`, `check tasks`,
  `check project`, and `knowledge-pending` operations; declare its Python/PyYAML environment explicitly
  and keep every operation out of ordinary Full gates.
- Preserve one complete, addressed, tool-independent Knowledge Gate algorithm in Full canon. It must
  define semantic carrier reading, full identifier discovery, collision/unresolved handling, selected
  section extraction and hashing, pending/removed comparison, threshold outcomes, and the hard stop on
  indeterminate input without prescribing Python or a shipped helper.
- Replace helper-based init/update verification with explicit owning-workflow postconditions and retain
  selected-task, pre-write structural checks in the status/event contracts.
- Remove numeric validity and truncation for event `summary` and status `title`, `goal`, `value`,
  `outcome`, and `lifecycle_verbatim`; retain one-line/shape requirements and prompt-only concise-writing
  guidance, including “brief, normally no more than 120 code points” for `summary`.
- Preserve the old board conversion as a self-contained, pinned-release-addressable
  `tools/migrations/2.0.0/` bundle. Its route declares Python/PyYAML, gives a no-runtime stop before any
  receiver write, and preserves source values without prose-length truncation.
- Keep compiled task traces and generated hidden landings for every recognized task directory, including
  tasks with no HL. Remove top-level Tasks navigation and default public/current-status pages. Permit a
  status snapshot only through an explicit workflow-dispatch option as a disposable CI artifact that
  neither gates documentation deployment nor becomes a citation target.
- Update current Full canon, templates, configs, repository guides/translations, documentation contract,
  Unreleased compatibility guidance, active adapters, and assurance so the new boundary is coherent.

### Out of Scope

- A broad TFW-16 doctor covering behavior analysis, knowledge-gap judgment, remediation, or lifecycle
  orchestration; the doctor here reports only deterministic project/task health and status.
- Shipping a collector, doctor, migration utility, Python package, dependency declaration, or command in
  `.tfw/` or `editions/02-assisted`; adding any Assisted reference or code is forbidden.
- A public task catalogue, default current-status page, committed replacement cache, durable CI status
  URL, daemon, hook, automatic repair, or required diagnostic/build gate.
- A self-contained multi-platform migration binary or default agent-synthesized migration. An alternative
  implementation is acceptable only after it passes the shared conformance vectors and identical dry-run
  accounting, which is not part of this phase.
- Editing the known 123-code-point event, rewriting existing task/phase journals, mass-rewriting live
  `status.md` files, or rewriting historical changelog, migration, proposal, RF, REVIEW, snapshot, or
  knowledge evidence to pretend the old contract never existed. Explicit additive supersession notes are
  allowed where a current reader otherwise receives an unusable command.
- Promoting RTBO Fact Candidates into `KNOWLEDGE.md` or `knowledge/*.md`; that remains `/tfw-docs` and
  `/tfw-knowledge` work after an approved REVIEW.
- Choosing a release number, changing `.tfw/VERSION`, tagging, publishing, or pushing; `/tfw-release`
  owns those decisions after this task closes.
- Removing the independent workflow word-count design rule or the knowledge topic/fact-count controls;
  they have different consumers and are not prose validity checks addressed by RTBO.

### Prospective scope rulings

1. **One phase.** Full canon, payload deletion, upstream replacements, migration route, adapters, docs,
   and compatibility prose form one cutover. Splitting would knowingly leave an intermediate release
   whose instructions name absent behavior or whose payload still signals the dependency being removed.
2. **The script decision is closed.** A script remains only as upstream maintainer tooling under `tools/`;
   no executable remains in Full or Assisted. `tfw_doctor.py` is deliberately narrower than TFW-16.
3. **No public list by default.** Hidden task landings are link infrastructure, not a task catalogue.
   The only status list is an explicitly requested CI artifact with finite platform retention.
4. **No synthetic parser as canon.** The method specifies semantic results and error outcomes. Regex-only
   YAML interpretation is prohibited; a locally written disposable implementation is permitted only when
   it satisfies the same semantics and stops on uncertainty.
5. **Knowledge promotion is later.** Current implementation canon changes now; verified-knowledge
   promotion remains behind the post-review `/tfw-docs` and `/tfw-knowledge` gates.

## 6. Technical Guidance

- Preserve history with Git renames before editing: `gen_index.py` is the source of
  `tools/tfw_state.py`; `migrate_board.py` is the source of the versioned migration executable; their
  tests move similarly. Then subtract index rendering/freshness instead of cloning the monolith.
- Keep `tfw_state.py` importable and side-effect free. Put presentation/CLI concerns in
  `tfw_doctor.py`; put docs presentation in `gen_docs.py`; keep the migration bundle self-contained so a
  pinned old-project recovery does not depend on today's maintainer library.
- Prefer a JSON report carrying operation, contract/shape applicability, inputs seen, material findings,
  indeterminate findings, advice, compatibility notes, and records. Stable ordering and explicit empty
  arrays make both human diagnosis and conformance tests cheap.
- Preserve current exact identifier grammar, year nesting, phase-local state, team accountability,
  relative refs, transition graph, terminal outcome, event timestamp/offset, and unknown-input refusal.
  Remove only index product behavior and prose-length validity/truncation.
- Generate a task landing as a virtual page at the folder's output root. Do not generate a parent task
  catalogue as a side effect; landings can enumerate only that task's real compiled pages.
- The explicit CI status snapshot should capture stdout and exit metadata even for exits `1`/`2`, upload
  it with finite retention, and allow the site build/deploy to continue. It is diagnostic evidence for
  the caller, not a green/red gate.
- Use additive `> **Superseded by** ... (2026-09-06)` notes where historical guidance must remain but its
  command path no longer works. Do not silently edit released claims or research/task evidence.
- If implementation reveals that a listed VALUE path is unnecessary, omit it and report the smaller
  Candidate. If a new necessary constituent is required, apply the §4 authority rule before editing it;
  no new path may weaken the Full/Assisted/runtime/history/publication boundaries.

## 7. Definition of Failure

- ❌ Any tracked current-status cache, index generator/freshness check, or default public status list remains
  or is recreated under another name.
- ❌ `gen_index.py`, migration code, doctor/collector code, or a Python/PyYAML prerequisite remains in
  `.tfw/`, enters Assisted, or is required by an ordinary Full workflow/build.
- ❌ The no-helper Knowledge Gate omits semantic cases, uses regex YAML as authority, silently drops an
  input, or cannot state pending/removed/problem outcomes without the upstream tool.
- ❌ The 123 event is edited, exempted, allowlisted, or still causes a finding/non-zero result; any other
  numeric prose ceiling or automatic evidence truncation survives.
- ❌ Removing length validity also suppresses missing identity/accountability/refs, illegal transitions,
  malformed state, invalid time/offset, contradictory terminal state, or indeterminate input.
- ❌ Migration can write before dependencies and exact accounting are established, depends on a moving
  upstream module, or leaves pre-2.0 users with only “install Python somehow”.
- ❌ Removing Tasks navigation breaks direct/cited/bare task links or restores prominence through a
  generated catalogue/landing index.
- ❌ Doctor diagnostics, CI status generation, or documentation collection repairs files, gates an
  unrelated default run, changes Git, or becomes authority over task state.
- ❌ Historical evidence is normalized, released prose is silently rewritten, TFW-16 is claimed complete,
  a release number is chosen, or `/tfw-docs` knowledge promotion is performed in this phase.
- ❌ Active canonical and adapter instructions disagree, clean receivers require absent paths, the full
  suite/build fails, or immutable accounting cannot be replayed.

## 8. Phase Risks

| Risk | Mitigation |
|---|---|
| Moving a large monolith preserves accidental index behavior or drops a structural check. | Start with renames, classify every function/test by retained product, and use baseline conformance vectors plus deletion tests. |
| No-helper wording becomes an underspecified invitation to grep YAML. | One complete semantic algorithm, adversarial regex mutant, independent digest implementation, and hard stop on uncertainty. |
| `tfw-doctor` quietly expands into TFW-16 or a new gate. | Exact four-operation CLI, deterministic finding classes, no repair, no default live invocation, and explicit out-of-scope claims. |
| Migration loses portability when separated from the payload. | Self-contained pinned bundle, its own requirements/procedure, help without PyYAML, and zero-write runtime matrix. |
| Hidden task pages exist but bare directory links remain broken. | Generate one landing for every recognized task, including no-HL fixtures, and verify built URLs. |
| Optional CI output becomes a de facto maintained product. | Explicit dispatch only, finite retention, not in `site/`, not cited, non-gating, no committed output. |
| Removing numeric bounds leads to verbose status/event prose. | Keep direct concise/one-line authoring guidance and let projections wrap; do not turn style back into validity. |
| Historical instructions mislead or history is rewritten to avoid that. | Add dated supersession pointers only, preserve original bodies, and compare protected bytes from Baseline. |
