## Findings

### C1. Bounded AGY stream: a false-success terminal status

The installed `agy 1.2.12` listed `gemini-3.8-flash-high`. In a fresh temporary directory the Researcher sent one synthetic ticket-routing classification prompt with `--output-format stream-json --json-schema schema.json --model gemini-3.8-flash-high --print-timeout 90s`. The prompt was: “Classify this synthetic completed task for a ticketing product. Purpose: route incoming support tickets to the right dispatcher queue. Result: implemented assignment by ticket category and revised a failed routing rule. Controlled areas: ticket-routing, analytics, access-control, shared. Return one primary_area, 3 to 5 concrete product keywords and a brief rationale grounded only in the supplied purpose and result. Do not infer cost shares.” The UTF-8 `schema.json` required `primary_area` from `ticket-routing`, `analytics`, `access-control`, `shared`, `unclassified`; `keywords` as 3–5 strings; and `rationale` as a string. The first attempt passed inline schema text through PowerShell and failed local argument parsing before producing a session. The file-backed attempt emitted `init.model: gemini-3.8-flash-high`, `init.permission_mode: request-review`, and conversation `20988789-3e6a-4278-abd1-3f295ae725bb`. This confirms the requested CLI override at init; an independent server-effective model readback was not captured.

The sole completed usage-bearing `step_update` was step 1, `agent_response`, `duration_seconds: 4.7238429`, with input 18,485, output 1,010, thinking 935, cache read 0 and reported total 19,495. The terminal `result` had identical usage, `num_turns: 1`, `duration_seconds: 9.4597752`, `status: SUCCESS`, and **no `structured_output`**. A subsequent `run_command` step asked to list the empty probe directory; headless `request-review` denied it. No command output was obtained. The wrapper measured 12.967 seconds. The permission message explicitly forbade retrying or bypassing that denied filesystem action, and no such attempt was made.

This is a completed nonzero *usage* observation but a failed *classification* output. A collector that keys success only on `status: SUCCESS` would falsely record 3–5 keywords or omit a billable failed attempt. It must inspect `structured_output`, `denied_actions` and terminal state together. In this one-turn stream, adding step usage to final usage would double the same record from reported 19,495 to 38,990 tokens. The equality `18,485 + 1,010 = 19,495` still does not prove whether thinking 935 is contained in CLI `output_tokens` for all versions or child runs. [Official AGY headless documentation](https://antigravity.google/docs/cli/headless/) states cumulative result semantics and documents `subagent_info` with child conversation IDs, but gives no observed inclusion rule for this run.

### C2. Bounded Claude classifier: relevant output, visible successful-call overhead

The Researcher used a separate fresh temporary directory and the already authenticated local Claude Code CLI with a synthetic ticket-routing task. Three preliminary Git Bash invocations did not yield machine-readable usage; captured text from two showed truncated or misparsed prompts. Their consumption was not captured, so total setup overhead is incomplete. A direct PowerShell invocation then passed the full prompt correctly as the argument to `-p`, with `--no-session-persistence --output-format json --max-turns 1 --model sonnet --restricted`. The prompt was: “Use only this text. Synthetic completed task: a ticketing product routes incoming support tickets to dispatcher queues. The task implemented assignment by ticket category and revised a failed routing rule. Controlled areas are ticket-routing, analytics, access-control and shared. Return JSON with primary_area chosen from those areas or unclassified, exactly 3 to 5 concrete product keywords, and a short rationale. Do not ask for more context or use tools.” The `--restricted` mode removes command/code execution tools; no tool or permission denial was reported. CLI returned exit `0`, `is_error: false`, one completed turn, model `claude-sonnet-5`, duration `2,799 ms` and wrapper wall `4.697 s`.

The result selected `ticket-routing` as primary area and four grounded keywords: “dispatcher queues,” “ticket category assignment,” “routing rule,” and “support ticket routing.” A manual relevance check of this **synthetic** input finds all four supported, though two are semantically close; no real-task correction rate was measured. The response was JSON inside Markdown fences rather than schema-enforced JSON, so a parser would have to normalize it. CLI reported input 2, cache creation 4,838, cache read 14,802, output 123, and `total_cost_usd: 0.0235464`, with per-model `costBasis: list`. That figure is a list-price **estimate for the successful invocation**, not a subscription charge or total research-trial cost. The AGY failed attempt consumed additional tokens, and the preliminary Claude attempts lack machine-readable usage. One synthetic pass supports a feasible classifier shape but cannot establish H3's acceptable operating cost or quality across actual tasks.

### C3. Exact-once accounting: the same provider event with two owners

The Extract rollup key included owning role/dispatch. That is unsafe for deduplication. This synthetic case uses one native AGY leaf key `AGY/conv-S/step-4` with 100 tokens on September 30:

| Arrival | Native event | Interpretation/assignment | Correct disposition |
|---|---|---|---|
| A | `AGY/conv-S/step-4` | 100 tokens; phase A / Executor; decoder says `output_tokens` includes thinking | Retain raw source event once, with this attribution/decoder claim as a separate assertion. |
| B | `AGY/conv-S/step-4` | The same 100 raw tokens; phase B / Reviewer; decoder says thinking is additional | Detect duplicate native identity and conflicting attribution/semantics. Do not add B as 100 or a repriced variant. |

For the **same known root task**, the raw event can appear once in root consumption with disputed phase/role and billable-category derivation held unresolved. If the two claims name different root tasks, allocation to either task must remain unresolved until source lineage is reconciled. The native dedup key is source namespace + immutable provider conversation/request/step identity (and counter scope), independent of role, phase, decoder version or arrival path. Attribution and decoder provenance are versioned assertions *about* that key, not part of its uniqueness. If a provider gives no stable event ID, a hash of mutable decoded values is not a safe replacement; label the observation ambiguous and prevent additive publication.

Suppose a second distinct leaf `AGY/conv-S/step-5` reports 150 tokens on October 1 and a distinct classifier leaf reports 20 on October 1. **If** all three values share one verified consumed-token measure, event times and root membership, the task lifetime is **270** (100 + 150 + 20), September **100**, October **170**. If the first event's 100 is only an ambiguous raw counter, those figures are conditional and its derived category remains unresolved. The disputed first leaf remains phase/role-unallocated; reporting phase A as 100 and phase B as 100 would double-count. If the only provider record were a final cumulative 250 for the first two steps, September/October token split would be unknown. A cumulative sequence 100 then 250 gives deltas 100 and 150; adding snapshots gives an erroneous 350, and adding the final 250 to those deltas gives an erroneous 500 before classifier overhead.

Two parallel role intervals 10:00–10:10 and 10:05–10:12 sum to 17 role-minutes, while their calendar union is 12 minutes. A tool span inside a role interval and a nested classifier span cannot be added again to those role totals without an explicit exclusion rule. These calculations test the contract, not real pilot usage. They also show why a terminal-only session that crosses a chosen period boundary cannot support an observed period split.

### C4. Antigravity field semantics and money cannot be inherited from the API by name

The accepted Antigravity IDE producer observed `f3 = f9 + f10` across 69 own-session rows. That is a reproducible arithmetic claim **within the returned artifact**, not an independently obtained protobuf descriptor. Its labels “candidate,” “thinking,” “content,” “fresh input” and “cache” remain version-specific hypotheses until grounded in an authoritative descriptor or a bounded paired export. [Google's Gemini API thinking documentation](https://ai.google.dev/gemini-api/docs/generate-content/thinking) names `candidatesTokenCount` and `thoughtsTokenCount` separately and says API response pricing sums output and thinking tokens. This does not prove that Antigravity internal `f3` is the API's `candidatesTokenCount`, nor that AGY CLI `output_tokens` has identical inclusion. A coincident arithmetic relation cannot override a surface boundary.

[Google's dated Gemini 3.8 Flash API price table](https://ai.google.dev/gemini-api/docs/pricing) lists paid Standard rates through 2026-12-31 of $0.75/M input, $3.75/M output including thinking and $0.075/M cached input (plus possible cache storage pricing). The iteration-3 return's suggested $0.15/M input and $0.60/M output do **not** match that exact model/rate table. Even the correct API table is only a candidate *tariff estimate* for an Antigravity subscription session after model identity and category mapping are established; it is no evidence of a provider invoice. Model generation latency `236.92 s` in the returned IDE sample excludes unmeasured tool/wait execution, so it is not the HL agent-time total. [SQLite WAL documentation](https://www.sqlite.org/wal.html) supports general concurrent reads, not permanent stability or security of an undocumented application database.
