## Research Plan

### Gather

- Establish the exact locally available Antigravity, Claude Desktop and Codex applications, versions and modes; distinguish desktop applications from similarly named CLIs, SDKs and APIs.
- Find primary documentation for each exact surface's usage counters, execution-time events, monetary data, session identity, hooks, exports and child-agent coverage.
- Make small, isolated, benign local diagnostic attempts under HL §4.1, recording commands or UI steps, observed output and unavailable access without reading unrelated sessions.
- Define a common capability matrix with evidence labels: documented, observed, unavailable and unverified; record model, input/output/cache/reasoning, retry, reset and compaction gaps.

### Extract

- Map every surface's data fields to a task/phase/role observation and separate event counters from cumulative counters and account-level quota.
- Test whether the observed fields can support token volume, execution intervals and a dated tariff estimate or observed charge without double-counting.
- Identify the smallest supported first capture route and a fallback, including prerequisites and which TFW role units the route can actually bind.
- Record coverage limits for child sessions, parallel work, retries and platform boundaries before recommending an adapter.

### Challenge

- Challenge the leading route with a bounded repeat or cross-check against authoritative surface documentation and a deliberately ambiguous accounting case.
- Probe whether the route exposes a stable task/session key and whether time means agent execution, wall-clock elapsed, tool time or a different interval.
- Identify a false-positive route that reports quota or an estimate as task cost, and state how the pilot must label it.
- Return decision-changing gaps and the next iteration's targeted probes rather than claiming a complete three-platform integration.
