| Statement | Install and update obtain one pinned release by a blobless, depth-1, cone-mode sparse clone written by Git itself (`--filter=blob:none --sparse --depth 1`, `sparse-checkout set .tfw` for update or `.tfw editions` for install), cloned with `-c core.autocrlf=false -c core.attributesFile=`. A size check (`count-objects -vH`) follows the clone, because a host that ignores the filter exits 0 and still marks the clone partial; a result above about 2 MiB is disclosed as a full download. Git-rejected options take one disclosed fallback. Every framework file is checked by raw bytes (`hash-object --no-filters` against `ls-tree`), never by a filtered hash. An untagged Candidate uses `init` + `fetch --depth 1 <SHA>` + `checkout FETCH_HEAD`. Staging stays at `.tfw/.upstream/` because installed and immutable pinned texts name it; the clone lives in `.tfw/.upstream/.clone`, is deleted after the check, and sealing requires `git ls-files -- .tfw/.upstream` to be empty. A root `.gitattributes` allow-list keeps release archives framework-only. The new-task startup card compares the installed version with the newest exact `vX.Y.Z` tag through one `ls-remote` bounded by about 13 s on the agent's own command tool; it never updates. |
| Applicability | This repository's shipped Full install/update text and release archives from the first release that carries them; receivers adopt it through their next update after that release. Projects on 3.7.1 or earlier still run their installed fetch once (the README one-time request covers it). Git ≥ 2.25 with a host that serves filters (GitHub observed; GitLab, Gitea ≥ 1.16 documented; Bitbucket Cloud not). |
| Grounds and uncertainty | Measured on `v3.7.1`: update 679.57 KiB in Git Bash, PowerShell 5.1 and WSL, 95/95 byte-equal; install 774.34 KiB; release ZIP 0.5 MiB instead of 178.9 MiB; a filter-less host detected at 114.51 MiB; a full trial update 5 min 11 s with transfer under 1 s. `git archive --worktree-attributes` was light but made one round trip per file (156 s), and a no-flag archive in any partial clone prefetched the whole tree (≈114 MiB). Unobserved: the Codex sandbox, macOS, Git below 2.42, real filter-less hosts, the GitHub archive before a push. |

## Source and decision context

The owner's pain was first impressions and a growing repository: a new user cloned ≈123 MiB of the
framework's own task history, and every update moved ≈114 MiB while `.tfw/` was ≈1 MiB. The written
method removes the improvisation that caused it. The download was only 3–5% of a timed update, so the
remaining duration lives in the procedure; three repeats that never found anything were removed, and
everything that protects receiver state stays.

## Relations and current use

Read with D70. The version line is a startup-card row, not a notification service; it informs and the
operator still names the version. The version-line limit is the owner's choice (13 s), balancing
3–5 s ordinary checks against packet-dropping networks.
