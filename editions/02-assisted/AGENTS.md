# Контракт TFW Assisted для ИИ

Работай на языке последнего сообщения пользователя. Ставь цель и проверяемый результат выше буквального исполнения отдельной реплики. Не обещай автоматизм, которого нет.

## При старте

1. Прочитай `PROJECT.md`, затем этот файл. Убедись, что активна ровно редакция Assisted версии 1.0.
2. Используй стартовую сводку состояния. Если её нет, одной фразой сообщи: «Проверки Assisted недоступны; работаю по ручному порядку», — и применяй ручную сверку из `README.md`.
3. Чтение, знакомство и обычный разговор не создают `work/`, задачу, профиль или кандидата знания.
4. Строка `active_task = none` допустима: не задавай вопрос, пока не требуется долговечное действие.

## Перед первой долговечной записью

Долговечное действие — изменение результата, состояния проекта или общей памяти. До него:

1. Пойми желаемый результат и критерии. Задай вопрос только если ответ меняет результат или риск.
2. Определи автора. Один профиль в `people/` выбирается без вопроса. При нескольких используй допустимую локальную привязку; если её нет или устройство новое/общее/скопированное, задай один вопрос: «От чьего имени сохранить эту запись?» Выбор храни только на личном устройстве, не в проекте. Для автоматизации используй отдельный ID вида `automation:<имя>`.
3. Создай нужные статусные папки только сейчас. ID задачи: `YYYYMMDD-HHMMSS__handle__slug`; общего счётчика нет.
4. Создай `work/doing/<ID>/TRACE.md` до результата. Запиши поля:
   - `ID задачи`, `Владелец`, `Роль ИИ`, `Желаемый результат`, `Критерии`, `Статус: doing`, `Результат: не создан`, `Решение о знании: не принято`;
   - `## План от результата назад` до `## Ход работы`;
   - источники, предпосылки, решения и способ проверки по мере работы.

Одна задача и её изменяемый trace имеют одного владельца записи. Не создавай общий task board, общий счётчик, `CURRENT_USER` или общий trace. Несколько участников работают в разных task folders. Статус меняется переносом всей папки между `work/new`, `doing`, `review`, `done`, `blocked`; одновременно обнови поле `Статус`. Для `review` и `done` поле `Результат` содержит существующий путь от корня проекта.

## Перед сокращением контекста и завершением

Перед сокращением контекста сохрани в активном `TRACE.md` текущее решение, проверку и следующий шаг. Автоматический checkpoint лишь страхует этот след и не заменяет содержательную запись.

Перед завершением сверь: trace существует; обязательные поля заполнены; план стоит раньше хода работы; статус равен папке; путь результата существует; `Решение о знании` содержит путь кандидата либо краткое «не переносить» с причиной. Исправляй только безопасное и однозначное. Проверка завершения может запросить одно продолжение; если рассогласование осталось, сообщи его пользователю и не создавай цикл.

## Память и риск

`TRACE.md` — первичный источник и не переписывается ради памяти. Долговечную находку после проверки риска сохрани отдельным файлом `knowledge/inbox/YYYYMMDD-HHMMSS__handle__slug.md` со следующими полями: `ID кандидата`, `Источник`, `Автор`, `Проверка риска: пройдена`, `Факт`, `Основание`. ID уникален и не использует общий счётчик.

До общей записи передай полный будущий текст встроенной проверке риска. При результате `hold` не создавай файл. Секреты, ключи, токены и пароли не записывай ни в trace, ни в кандидата, ни в индекс. Медицинские, персональные, юридические, финансовые и safety-sensitive сведения удерживай и один раз спроси: «Можно ли сохранить этот материал в общей памяти проекта?» При сомнении удерживай. Служебная проверка распознаёт только формальные признаки секретов; смысловую границу соблюдаешь ты.

Не изменяй `knowledge/INDEX.md` автоматически и не выдавай `records/` за автоматически подтверждённые. В Assisted нет расписания, консолидации, продвижения, чистки, дедупликации или разрешения конфликтов. Такое действие возможно только как отдельная явно порученная работа с собственным следом.

## Переход с Light

Следуй `MIGRATION.md`. Сначала сохрани исходные `README.md`, `AGENTS.md`, `TASKS.md`, `memory/PROJECT.md`, traces и результаты с проверкой содержимого. Если уже обнаружены два активных контракта, не записывай ничего и задай ровно один вопрос из `MIGRATION.md`. Не изменяй смысл цели и не удаляй первичный след.
