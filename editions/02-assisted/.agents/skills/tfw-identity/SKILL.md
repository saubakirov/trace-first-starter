# /tfw-identity

Это внутренняя Markdown-процедура `AGENTS.md`. Выполняй её обычным чтением файлов, одним вопросом человеку при необходимости и обычным созданием Markdown-файла. Не запускай регистрацию и не создавай машинное состояние.

## Разделяй роли

Всегда держи раздельно пять фактов:

1. текущий участник разговора;
2. его роль в организации;
3. его роль в проекте;
4. владелец конкретной задачи из `work/<ID>/TRACE.md`;
5. роль ИИ в текущем цикле.

Выбор другого участника или роли в новом чате не меняет владельца существующей задачи. Профиль — заявленная атрибуция, а не проверка личности, полномочий или устройства.

## Что считать валидным профилем

Прочитай только регулярные файлы `people/*.md`; `people/README.md` исключи. Валидный человеческий профиль содержит ровно по одному непустому полю:

```text
Идентификатор: <identifier>
Отображаемое имя: <имя и фамилия>
Тип: человек
Роль в организации: <роль | не применимо | не указана>
Роль в проекте: <роль | не применимо | не указана>
```

Имя файла должно быть `<identifier>.md`, а identifier — состоять из строчных латинских букв, цифр, `_` или `-`. Невалидный файл покажи отдельно и не используй для автоматического выбора.

## Выбор участника

1. Перечисли валидные профили по отображаемым именам.
2. Если валидный профиль ровно один, примени явное правило одного профиля и назови человеку выбранное отображаемое имя.
3. Если профилей нет, предложи создать профиль по процедуре ниже.
4. Если валидных профилей несколько, спроси, кто сейчас работает, перечислив отображаемые имена. При явном ранее зафиксированном в текущем разговоре выборе используй его, пока человек не изменит выбор.
5. Если ответ не совпал однозначно с одним валидным профилем, уточни. Не выбирай первый, последний или ранее использованный профиль.

Для автономной роли Executor/Reviewer человеческий участник может быть `не применимо`: роль ИИ и владелец задачи всё равно берутся из trace и не смешиваются с человеческим профилем.

## Создание нового человеческого профиля

Сначала одним сообщением запроси недостающее:

> Как вас зовут? Назовите, пожалуйста, имя и фамилию. Какова ваша роль в организации и в этом проекте? Если роль одна, достаточно назвать её один раз.

Ничего не записывай, пока явно не получены имя, фамилия и обе роли либо допустимые значения `не применимо`/`не указана`. Если фамилия отсутствует или порядок частей имени неоднозначен, задай одно естественное уточнение.

Identifier выводится из подтверждённой фамилии:

- кириллица транслитерируется: `а б в г д е ё ж з и й к л м н о п р с т у ф х ц ч ш щ ы э ю я` → `a b v g d e e zh z i i k l m n o p r s t u f h ts ch sh shch y e yu ya`; `ь` и `ъ` удаляются;
- латиница переводится в нижний регистр;
- пробелы и разделители становятся `-`, повторные `-` схлопываются, прочие символы удаляются;
- пустой результат недопустим.

Перед созданием заново перечисли `people/*.md` и проверь точный путь `people/<identifier>.md`. Если он занят, не открывай и не перезаписывай его как нового человека: запроси смысловое уточнение и используй подтверждённый вариант `surname-given-name` либо `surname-<уточнение>`. Молчаливый числовой суффикс запрещён.

Создай только этот новый файл обычной файловой операцией с пятью полями из шаблона. Затем перечитай файл и повторно проверь имя пути, identifier, тип, отображаемое имя и обе роли. При ошибке сообщи о ней; не объявляй профиль готовым по памяти.

## Закрытые сценарии

| Состояние | Действие |
|---|---|
| 0 валидных профилей | спросить имя, фамилию и роли; создавать только после полного явного ответа |
| 1 валидный профиль | применить и назвать правило одного профиля |
| 2+ валидных профиля | спросить выбор по отображаемым именам |
| Кириллическая фамилия | применить таблицу транслитерации |
| Латинская фамилия | нормализовать в нижний identifier |
| Фамилия отсутствует/неясна | уточнить; ноль записей |
| Target занят | не перезаписывать; запросить смысловой вариант |
| Невалидный профиль | исключить из выбора и сообщить причину |
| Явный выбор в разговоре | использовать только выбранный валидный профиль |
| Автономная AI-роль | участник может быть `не применимо`; owner и AI role брать из trace |

Процедура не сохраняет выбор на компьютере, не создаёт отдельное машинное состояние и не обещает защиту операционной системы.
