# TFW Assisted 1.5

Assisted помогает доводить повторяющуюся работу до принятого результата, не превращая проект в полный формальный процесс. Он отделяет постановку, исполнение и независимую проверку, хранит устойчивый след задачи и оставляет человеку окончательное решение.

## Начало работы

1. Скопируйте **содержимое** этой папки в корень проекта.
2. Откройте новый чат в корне проекта и попросите ИИ прочитать `PROJECT.md`, `AGENTS.md` и этот файл.
3. Если `PROJECT.md` не инициализирован, ответьте не более чем на три содержательных вопроса о проекте, участниках, результате, приёмке и ограничениях.
4. После инициализации начните задачу обычным запросом или `/tfw-plan`.

Версия пакета находится только в `VERSION`. Отсутствие стартовой сводки нормально: в Assisted 1.5 нет lifecycle hooks. Работайте по ручному порядку ниже.

## Ручной порядок — штатный режим

```text
/tfw-plan
    ↓ согласованный TRACE.md и Gate 0
/tfw-handoff
    ↓ результат + REPORT.md + самопроверка
/tfw-review
    ↓ независимый PASS / FAIL
решение о знании
    ↓
человеческая приёмка → done либо возврат тому же исполнителю
```

- Планировщик не исполняет собственный план.
- Исполнитель не выносит независимый вердикт.
- Ревьювер не исправляет результат и не меняет постановку.
- При исправлении используется тот же исполнитель; при повторной проверке — тот же независимый ревьювер, который заново проверяет весь контракт.
- Пользователь принимает результат только после независимого `PASS` и выполненного решения о знании.

## Явно разрешённая автономная координация

Пользователь может одним решением разрешить планировщику координировать отдельные задачи исполнителя и ревьювера в пределах одного утверждённого task ID. Это разрешение не позволяет менять постановку, обходить приёмку, создавать параллельных писателей или запускать посторонние задачи.

Перед началом фазы и перед каждой отправкой координатор проверяет наличие нужной операции и точный адрес существующей роли. Потеря адреса, неоднозначность, отсутствие безопасного прерывания или неполная операция означают остановку либо переход к ручному порядку. Автоматический дубль роли не создаётся.

## Устройство проекта

```text
PROJECT.md                 контекст конкретного проекта
AGENTS.md                  постоянный рабочий контракт
people/                    заявленные профили участников
knowledge/                 подтверждённые записи и кандидаты
work/<ID>/TRACE.md         постановка и живой след задачи
work/<ID>/REPORT.md        отчёт исполнителя
work/<ID>/REVIEW.md        независимый вердикт
шаблоны/                   практические результаты
.agents/skills/            пять команд Assisted
```

Новый ID задачи имеет форму `YYYYMMDD-HHMMSS__slug`. Путь задачи не меняется при переходах состояния. Текущее состояние находится внутри `TRACE.md`; общий счётчик не используется.

## Участник

Профиль — заявленная атрибуция, а не проверка личности или полномочий. Человеческий профиль хранит отдельно имя, роль в организации и роль в проекте. Владелец существующей задачи берётся из её trace и не меняется из-за нового чата.

Участник выбирается по Markdown-процедуре `.agents/skills/tfw-identity/SKILL.md`: агент читает валидные `people/*.md`, применяет правило одного профиля только при одном валидном профиле, а иначе спрашивает человека. Новый профиль создаётся обычной файловой операцией только из явно подтверждённых имени, фамилии и ролей; существующий файл никогда не перезаписывается. Выбор не сохраняется вне проекта или текущего разговора.

## Практические шаблоны

- `шаблоны/заметка.md` — структурированная рабочая записка;
- `шаблоны/план_работы.md` — постановка от результата и приёмки;
- `шаблоны/документ_A4.md` — законченный пример документа;
- `шаблоны/build_a4.py` — автономная сборка Markdown → HTML;
- `шаблоны/презентация.html` — автономная презентация;
- `шаблоны/overlay/theme.css` и `шаблоны/assets/tfw-mark.svg` — ограниченная локальная настройка.

Сборка A4:

```text
python шаблоны/build_a4.py SOURCE OUTPUT TITLE
```

Допустимы только локальные регулярные theme/mark-файлы внутри `шаблоны/`. Сеть не требуется. Интерфейс `assisted-theme-v1` закрыт: один `:root` и шесть разрешённых свойств.

## Обновление

Запустите `/tfw-update`, укажите доверенный каталог новой публичной версии и сначала получите полный read-only план. Агент читает статические manifest/policy, классифицирует каждый путь и останавливается на одном gate с точным списком create/replace/delete. После одобрения он повторно проверяет baseline, применяет обычные файловые операции и снимает after-manifest. `work/`, знания, профили, `PROJECT.md`, изменённые шаблоны, неизвестные файлы и посторонняя `.codex/` сохраняются.

Обратное направление создаёт только обезличенный кандидат. Оно не изменяет публичный core до отдельной независимой проверки и нового решения о выпуске.
