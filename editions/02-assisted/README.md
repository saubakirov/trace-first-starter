# TFW Assisted

Assisted — русскоязычный стартовый набор для повторяющейся работы в Codex. Он помогает не терять цель, создавать след до результата, видеть статус по папке и готовить долговечные знания без общего списка задач и ручных напоминаний на каждом шаге.

Скопируйте **содержимое** этой папки в корень проекта. Не работайте внутри вложенной `02-assisted/`.

## Запуск

1. Откройте `PROJECT.md`: уточните цель, образ результата, участников и ограничения. Строки `Активная редакция` и `Версия редакции` не меняйте.
2. Для каждого человека создайте один файл профиля по правилам `people/README.md`. Если работает один человек, достаточно одного профиля.
3. Откройте корень проекта в Codex и начните новую сессию.
4. Codex покажет уведомление о новых проверках проекта. Просмотрите три определения из `.codex/hooks.json` и доверьте их только после проверки путей. В CLI это делается через `/hooks`.
5. Начните ещё одну новую сессию. В начале должна появиться короткая сводка `TFW Assisted активен` с корнем, участником и задачами.

Доверие привязано к точному определению проверки. После изменения `.codex/hooks.json` потребуется повторный просмотр и доверие. После изменения `AGENTS.md` или рабочего контракта начните новую сессию.

## Как идёт работа

Обычный вопрос, чтение или знакомство с проектом ничего не создают. Перед первым изменением результата Codex создаёт задачу в `work/doing/` и её `TRACE.md`: владелец, роль ИИ, желаемый результат, критерии и план от результата назад уже записаны. Статус задачи — имя родительской папки: `new`, `doing`, `review`, `done` или `blocked`.

Во время работы след хранит источники, решения, проверки и путь к результату. Перед сокращением контекста служебная проверка добавляет идемпотентный checkpoint. При завершении она один раз сообщает о рассогласовании следа и файлов; повторного цикла исправлений нет.

Долговечная находка сначала становится отдельным кандидатом в `knowledge/inbox/`. Секреты туда не попадают. Медицинские, персональные, юридические, финансовые и иные чувствительные сведения удерживает сам Codex и задаёт один короткий вопрос перед общей записью. Служебная проверка распознаёт только детерминированные признаки секретов и не понимает смысловых категорий.

## Если автоматические проверки недоступны

Codex должен сказать: **«Проверки Assisted недоступны; работаю по ручному порядку.»**

Ручной порядок остаётся рабочим:

1. до результата создать `work/doing/<ID>__<тема>/TRACE.md`;
2. записать владельца, роль ИИ, результат, критерии и обратный план;
3. вести решения, проверки и пути к файлам;
4. перед завершением сверить статус папки, след, результат и решение о кандидате знания.

Работу можно продолжить, но нельзя называть её автоматически проверенной.

## Честные границы

Assisted не выполняет периодическую консолидацию памяти, не продвигает кандидатов в подтверждённые записи, не чистит и не обновляет индекс автоматически. Он не вводит организационные режимы, не аутентифицирует людей, не подтверждает полномочия, не гарантирует безопасное одновременное редактирование одного файла и не работает при закрытом Codex.

Для перехода существующего Light-проекта сначала следуйте `MIGRATION.md`: исходные файлы и traces должны сохраниться до замены активного контракта.
