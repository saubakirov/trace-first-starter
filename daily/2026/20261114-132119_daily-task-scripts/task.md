## 2. Goal, Value and Boundaries

Цель: три скрипта в составе расширения Daily — `new_record.py`, `check_record.py`,
`daily_close.py` — заменяют ручное создание записи, её проверку и замер при закрытии; скилл и
справка по учёту вызывают их; скрипт сопровождающего воспроизводит A/B-замер.

Ценность: закрытие быстрее и надёжнее (одна команда вместо поиска журнала, collect, receive и
ручной строки ревизии) и повторяемый тест вместо ручных запусков.

Границы: `.tfw/extensions/daily-task/` (новая `scripts/`, SKILL.md, references/economics.md,
installation.md, Claude-точка входа), установленная Claude-обёртка, `tools/` (A/B-скрипт, тесты,
README), `docs/scripts/gen_docs.py`, `.tfw/CHANGELOG.md`. Правила скилла и контракт учёта не
меняются; без профилей Codex/Antigravity и v2-схемы. Коммиты — после «ок» заказчика; push — только
по просьбе: `git push -u origin daily-task-scripts`.

Проверка готовности: pytest зелёный, включая новые unit-тесты в `tools/tests/`; обёртки побайтно
равны источникам; installation.md и gen_docs.py знают новые файлы; независимое ревью субагентом
старого и нового текста не находит потерянного гейта; A/B на `transcard-migration`, по 3 прогона
на вариант, время закрытия отдельно, разрешения сначала проверены на одном прогоне.

2026-11-14, сужение по решению заказчика: в MR остаётся только `daily_close.py` (замер при

Продукты (не закоммичены): `.tfw/extensions/daily-task/scripts/daily_close.py`,
`.tfw/extensions/daily-task/{SKILL.md,references/economics.md,installation.md,entries/claude-code/SKILL.md}`,

`tools/README.md`, `.tfw/CHANGELOG.md`.

Решения (2026-11-14):
- `daily_close.py` вызывает существующий helper учёта (`status_fields`, `collect`, `failure`,
  `receive`, `report`), своих правил учёта не вводит. Версия источника — из поля `version` журнала.
- В сабагенте `CLAUDE_CODE_SESSION_ID` указывает на родителя; автоматически это не различить
  (`CLAUDE_CODE_CHILD_SESSION=1` есть и в основной сессии), поэтому правило записано в справке.
- `gen_docs.py` не меняется: он публикует только Markdown, новых `.md` нет.
- После серии 1 (три скрипта, ускорения нет) заказчик выбрал вариант 2 — только `daily_close.py`:
  «Прогони еще вариант 2»; на вопрос о ценности учёта: «да учет экономики это одна из задач».
  `new_record.py`, `check_record.py` и общий модуль убраны, `daily_close.py` самодостаточен;
  SKILL.md и справка — побайтно тот текст, что прогнан в серии 2.
