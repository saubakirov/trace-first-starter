## 1. Objective

Cut review and knowledge-closure instructions to one precise, sequential contract.
Delete six support files, shorten nine owners/consumers, preserve independent
product/value/source/reality judgment, and prove a material reduction on the final tree.

## 2. Scope

### In Scope

- One REVIEW trace with Map → Verify → Judge → Decide sections.
- Three short risk lenses inside `review.md`; no mode WAIT or mode files.
- Claim/boundary-driven verification; counts and ratios are not closure authority.
- One Learning Receipt for selected correction/docs/knowledge/roadmap/debt/local/defer
  dispositions; no-signal creates no filler work.
- Separate docs and verified-fact write ownership with one closure route.
- Compact, source-resolvable KNOWLEDGE index.
- Exact compression, semantic, cross-domain, rendering, and protected-scope proof.

### Out of Scope

- New framework files, artifacts, terms, statuses, scripts, hooks, registries, or runtime.
- Other tasks, exact config values, knowledge state/topics, extensions, adapters,
  migration, release, and Phase E/F work.
- Historical trace rewrites and all remote publication.

## 6. Technical Guidance

- Canonical ownership: conventions = meaning; review workflow = action/Role Lock/STOP;
  REVIEW = output; glossary/KNOWLEDGE = indexes; docs/knowledge = distinct destinations.
- Put the three risk lenses in one compact table or bullets in `review.md`; do not
  reproduce old mode files.
- Put Map/Verify/Judge/Decide in one REVIEW template; do not reproduce old stage files.
- Preserve old candidate-section/marker discovery but generate only selected learning
  in new RF/RES/REVIEW artifacts.
- Shorten KNOWLEDGE rows in place and rely on existing source links. Do not renumber,
  merge silently, or create an archive.
- Count with UTF-8 `len(re.findall(r"\S+", text))` and `splitlines()` on exact HL corpora.
- Exact config values and other tasks remain completely untouched.

## 7. Definition of Failure

- Any HL §6 failure occurs.
- Any new framework file/type/executable/registry appears.
- Deleted support files survive, are renamed, or are copied into another owner.
- Review loses claim/boundary/attack/result/verdict structure or product/value/source
  authority.
- Any D/source/legacy/fact link is lost or ambiguous.
- No-signal still requires a filler table or marker.
- Any scenario or reduction ceiling fails.
- A tenth live consumer or sixteenth affected framework path changes.
- Another task, config/state/topics, adapters, Phase E/F, or remote state changes.
- Executor writes REVIEW, claims acceptance, or crosses RF STOP.
