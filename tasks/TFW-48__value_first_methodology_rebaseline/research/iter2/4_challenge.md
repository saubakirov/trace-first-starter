### Surviving value-proof configurations

V1–V10 remain valid **records**, not complete global review modes. The complete-method
constraints are:

1. every claimed deliverable has V1 or V2 local proof;
2. each crossed source/interface seam adds V3–V6;
3. each stakeholder/live claim adds V7 or V8;
4. any triggered proof that is deferred adds V9 or V10 with owner/due/non-claim; and
5. discrepancy, irreversible impact, or weak evidence can expand packaging without
   changing the proof obligation.

This eliminates any complete configuration containing only V3–V10, but does not
eliminate those rows as additional records.

## Findings

### C1. Failure cases strengthen M5's selectors rather than forcing a heavy default

| Counter-case | Attack on M5 | Result |
|--------------|--------------|--------|
| Atamat TFW-2.100 | Full workflow repetition still missed scope, a 507-line breach, and false completeness | More local prose is not sufficient; M5 survives only with observable proof/gates |
| AFD-10 | A cited Helpdesk source was loaded as a reference but its migration infrastructure was omitted | Reference-only R1 is eliminated for cross-source claims; add V3–V6 seam proof |
| HD-26 | Mocked tests and agreeing artifacts missed impossible live PostgreSQL migration behavior | Local proof alone fails a live seam; add stakeholder/environment proof or explicit debt |
| HD-30 | Locally correct frontend/backend phases failed at repeated-query/scalar contract | Grouped seam proof survives only if it inspects both sides and their relation |
| AFD-38 | Initial approval was retracted after the project single-registry value was inspected | E3 discovery and reviewer authority over applicable project values are mandatory |
| TFW-36 | Public content needed repair after three claim-integrity incidents | External claims trigger source-audit seam proof and risk expansion; generic compact review is insufficient |
| Atamat security hardening | Layered DDoS/rate-limit controls have different state, cost, UX, and infrastructure seams | High-risk claims require control-typed examine/test evidence; one global pass percentage is inadequate |
| Yandex Cloud migration | Infrastructure changes cross provider, secret, state, rollback, and human-execution boundaries | R9/R12 gates, live proof, and explicit unexecuted/value-debt states survive; compactness cannot waive them |
| AFD-31 | Incident-driven umbrella was closed without executing its stale original plan | Honest closure can be value-preserving when a ledger routes every remaining item and live evidence shows which risks were resolved elsewhere |

The security and migration cases do not require staged files for their own sake. They
require greater assessment depth/coverage and multiple proof methods. NIST
[SP 800-53A Rev. 5](https://csrc.nist.gov/pubs/sp/800/53/a/r5/final) independently
defines examine, interview, and test methods and makes assessment procedures tailorable
to required assurance and risk tolerance. NIST does not validate TFW's exact
configuration, but it supports selecting proof depth/coverage from the protected
control rather than imposing one universal artifact package.

**H1 attack:** H1 survives only as rule-typed locality. TFW-2.100 falsifies
repetition-as-enforcement, AFD-10 falsifies reference-only use, and R9 counterexamples
falsify universal compression.

### C2. Learning and extensions fail in different ways

The Coordinator's Extract correction survives the counter-cases:

- learning fails when a selected signal lacks a disposition/destination/due relation;
- extensions fail when a project policy is undiscoverable, stale, unsupported, or
  silently loses precedence; and
- either can be correct while the other is absent.

AFD-31 is useful counter-evidence to "every closure needs promotion": remaining issues
were routed into proposals and AFD-37, while obsolete umbrella work was honestly
closed. The closure ledger is a learning transaction; AFD's project rules are separate
extension records.

The minimum surviving receipt is disposition-dependent:

| Disposition | Minimum receipt |
|-------------|-----------------|
| Reject / remain task-local | State + reason |
| Promote / merge / derive | State + destination backlink + responsible actor |
| Defer | State + destination or due event + responsible actor |
| Batch | Per-item state; an artifact-level `processed` marker is insufficient |

**H3 attack:** H3 survives as "existing capture locations are sufficient only when the
transaction is findable." It does not justify a universal central registry or an
extension registry disguised as a learning receipt.

### C3. Local proof is universal; proof depth and packaging are claim-typed

The strongest attack on grouped review is hidden omission: a group can make it unclear
which deliverable, seam, owner, or due event was actually verified. The surviving
grouped package therefore needs a small claim ledger:

```text
claim/deliverable
  → local proof
  → triggered seam proof(s)
  → triggered stakeholder/live proof
  → evidence or explicit debt
  → owner and due event if debt remains
```

This ledger may live inside one compact review. Separate stage files become useful when
discrepancy, number of independent seams, multiple assessors, or irreversible exposure
makes the inline record unscannable.

NIST's evidence-method distinction is also counter-evidence to "100% file review is
always stronger." Coverage of every file can still omit an interview with the
authority, a live test, or the actual seam. The correct denominator is the claim/control
set, not automatically the file set.

Two additional challenges apply to the whole ledger:

1. D4-D must split into **target** and **descriptive measurement**. A target is
   normative and needs owner/response/override; a measurement is inventory-only and
   needs provenance but no breach.
2. A structural existence gate (for example at least one evidence record) is not the
   same kind of tunable threshold as 42% sampling, 200 lines, or five tasks. Structural
   gates need construct validity; tunable thresholds additionally need outcome/cost
   calibration.

The mature-project breaches do not select new values. The absence of an incident at 54
facts or 388 index lines also proves nothing about retrieval cost. Conversely, the
routine cases' self-selected 67–100% review does not prove that 42% is unsafe; it only
shows the floor did not bind those cases.

**H2 attack:** H2 survives after narrowing: keep hard numbers only when their semantic
type and protected failure justify hardness; treat other values as warnings, sampling
defaults, targets, or measurements. No individual exact value is validated.

### C5. H4 output counts are not independent sample sizes

The arithmetic in Gather is internally consistent:

- `4 × 2 × 4 + 8 = 40`;
- `12 × 2 × 4 + 16 = 112`; and
- `12 × 2 × 7 + 28 + 24 = 220`.

The adversarial inference check changes how those totals may be described:

| Proposal | Independent-case ceiling | Repeated/nested outputs | Surviving claim |
|----------|--------------------------|-------------------------|-----------------|
| 40 | Four cases, two per family | Profiles, conditions, and eight repeats share cases/source packs | Protocol operability, scorer agreement, cost/runtime only |
| 112 | Twelve cases | 96 crossed outputs plus 16 repeats are nested within cases | Variance/reliability calibration and feasibility; no confirm/refute H4 claim |
| 220 | Twelve main cases plus two pilot case packs | 168 main cells, 28 pilot cells, and 24 repeats are not 220 independent cases | Candidate inferential layout only after prospective power/multiplicity/model checks |

The 220 layout could still fail even if every output completes:

- case is the principal independent unit; repeated cells cannot replace case diversity;
- two inquiry families may require separate variance/effect assumptions;
- profile × strategy interactions can invalidate a pooled effect;
- scorer disagreement and case difficulty are clustered;
- model/surface/system/tool versions must be pinned or treated as a time-varying
  package;
- the 10% rerun reserve is a cost assumption, not a missingness/stopping rule; and
- API-reference dollars and Codex credits are different surfaces, while human hours
  lack owner rates and do not include every supervision/storage burden.

The 40-output proposal remains incapable of confirming or refuting H4. The 112- and
220-output proposals remain unapproved and not inference-ready merely because their
costs are estimated.

**H4 attack:** H4 remains unresolved/inconclusive. No evidence generated in this
iteration changes its truth status.

### C6. K3 survives as semantics, not as uniform trace volume

Across routine and counter-cases, five obligations withstand attack:

1. product purpose/applicable project values are load-bearing;
2. role and lifecycle authority must be explicit before protected actions;
3. reality/evidence can override agreeing plans and reports;
4. independent judgment must be able to inspect claims, sources, seams, and actual
   state; and
5. selected durable learning needs a visible disposition.

What does not survive:

- one staged artifact set for every obligation;
- one global file-review percentage as assurance;
- central routing of every artifact;
- extension registration without observed discovery/freshness;
- local verification as proof of a crossed seam; or
- a numeric threshold without a semantic lifecycle.

K3 overhead is therefore controlled by record/claim triggers and packaging, not by
removing the obligations.

## Metacognitive Check

**Did Challenge discover something new?**

Yes:

1. D4-D incorrectly combined a normative target with a nonnormative descriptive
   measurement and must split in synthesis.
2. The 35-line adapter rule is currently active and met by the research skill; its
   defect is missing unit/enforcement semantics, not obsolescence.
3. H4's output totals obscure that the independent-case ceiling is four, twelve, and
   twelve-plus-two—not 40, 112, and 220.
4. AFD-31 shows that closure without execution can preserve value when disposition is
   locally verified and open work remains findable.

The stage also confirmed M5, but only after eliminating global V selection and adding
claim-triggered proof records. A remaining limitation is that no weaker-profile
behavior was newly executed; rule-locality findings remain mechanism/case evidence,
not profile-effect evidence.
