Before implementation
---------------------
Observed on the pre-change code before Phase AB edits:

board_id= HD-30
plain= normalizetext() and workingdays
current= None

The cause was the board parser's unanchored search for `[A-Z][A-Z0-9]*-\d+`.
It extracted the valid prefix `HD-30` from the malformed whole candidate `HD-30b`
before the shared legacy parser was consulted. `_plain()` independently stripped every
underscore as Markdown markup.

Result
------

underscores remain byte-for-byte intact.
